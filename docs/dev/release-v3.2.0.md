# 阡陌 v3.2.0 GitHub Release

v3.2.0 收录 v3.1.1 之后合入 main 的全部改动（#277–#298），主要是桌面版照 Claude Desktop 做的第二轮，外加一次基座同步：
- 主窗口改为 Work | Code 两种模式，加设置卡片与局部导航。
- Code 模式的本机会话：Claude Code、Codex 和四种 ACP agent，独立工作树，Remote 同步，中枢连不上时也能打开。
- Work 的常驻会话与「开始一项工作」。
- 分栏与悬停侧栏。
- 中枢缺省把智能体开成自动审批。
- 修了客户端卡顿的几处。
- 基座 qianmopi 同步到上游 v18.14.1，工具链升到 Bun 1.4.4。

标签打在 #298 的合并提交上，产品代码以它为准：main `ab968ec0` 加上基座同步（#298）。同一个 PR 里还有这次的文档改动（本文、路线图），可以用 `git diff --stat ab968ec0 v3.2.0` 核对。

**与 v3.1.0 不同，本版产品代码不是内测环境上记下的那一份**：仓库里最近一次部署记录是 10 月 25 日的 `af903b8a`（#283），之后合入的 #285–#298 没有部署记录，其中包括这次基座同步（见「部署与验证」）。

发行形式与 v3.1.0 相同：源码归档加 `SHA256SUMS`，不附可执行文件和安装包。v3.1.1 附的 `.dmg` 是旧的壳，没有本版的 Code 本机会话与离线页。识别 `qm` 产物以编译进去的源码提交为准（CONTRIBUTING §11）；`qmo` 与桌面壳仍自报 0.1.0。

下文写的是代码已经实现的能力。只在测试替身、假进程、假模型或本机上验证过的部分逐条注明。逐包状态见[路线图](./roadmap.md)与 [`qmo-local.md`](./qmo-local.md) §8。

## 变化

### 两种模式与即时响应（P37.13）

- **后台局部导航**（#280）：
  - 后台各页之间换页走局部请求，不再重载文档；整页与局部应答都带 `Vary`。
  - 先改后同步：后台开关、表单的「保存」、权限模式、发消息都先改界面，失败时退回原样，并在原处写明原因。没送出的消息留在对话里，可以「重试」。
  - 前台与后台用同一套外观变量。
- **Work | Code**（#281）：
  - 主窗口只留 Work 与 Code 两种模式。管理后台改成 Work 面上方的设置卡片，「管理后台」入口改名「设置」，主页面上不再有通往后台的文字链接。`/admin/<区域>` 的地址照旧能直接打开，打开后是开着卡片的 Work 面。
  - 壳加了本机 agent 检测，首帧按上次的布局画。
- 桌面壳里后台页侧栏的标志让开了 macOS 红绿灯（#277）。

### Code：本机会话（P37.14–P37.16）

- **识别本机 agent**（#279）：`qmo agents --json` 按 magpie 的做法找本机装了哪些编程 agent。Claude Code、Codex、Gemini CLI、Qwen Code、opencode、dsh 能驱动；Cursor CLI、Kimi Code、Droid、Copilot CLI、Goose 只识别，不能驱动。识别时不读任何 agent 的凭据与配置内容。
- **本机会话**：
  - 支持的 agent：Claude Code（#283）、Codex（#285），以及经 ACP 接入的 Gemini CLI、Qwen Code、opencode、dsh（#289）。
  - 驱动方式：随包 `qmo` 里的运行器 `qmo code serve` 用各 agent 的官方协议驱动它们（`claude -p` 流式 JSON、`codex app-server`、ACP），用的是用户自己在这台电脑上的登录。
  - 新包 `@qianmo/harness`：协议代码从节点包抽出来放在这里，节点上的常驻底层与本机会话共用。
  - Code 页的内容：会话按文件夹分组，有转录、征询卡片、四档权限模式与 Git 变更面板。
  - 页面只经壳的 `qmo_local_*` 命令与一条有序事件通道找运行器，会话不经过中枢。
- **工作树与补全**（#291，P37.14d）：
  - 在 Git 仓库里可以开独立工作树会话。删会话时，干净的工作树一并删掉，有改动的留下。
  - 变更面板补上非 Git 文件夹、未跟踪文件、二进制与大文件。
  - 会话可以改名、删除，删除后 10 秒内可撤销。
  - 窗口不在前面时，一轮做完或等你确认会发系统通知、加角标。
  - 退出 Qmo 时有会话在跑，先问一句。
  - 壳的设置窗多了「Code」一节。
- **Codex 帧序**（#292）：Codex 通道读到 `turn/start` 的答复就交出输入，一轮里的帧按 app-server 发出的先后排。
- **Remote**（#286，P37.15）：
  - 开关：每个本机会话一个 Remote 开关，缺省关。没有会话开着 Remote 时，这台电脑不连中枢。
  - 链路与同步：开着时，运行器拨出设备链路（中枢 `/v0/client/link`），把会话的抬头与记录同步到中枢。
  - 别的设备：同一账号的浏览器或另一台桌面版能在 Code 列表里看到这个会话。设备在线时可以续写、答征询、中止；离线时只读。
  - 不同步的：完整路径、文件内容、变更面板与正文增量。
  - 适用范围：只给个人账号，中枢要接设备账本。
  - 副本存放：按账号隔离，存在中枢配置根下。单个副本至多 16 MiB；一个账号至多 100 个副本，合计 256 MiB。
- **离线打开 Code**（#296，P37.16）：
  - 中枢连不上（网络不通或被限流）时，壳的离线页多一个「打开本机会话」，进的是壳自带的精简 Code 页。
  - 在这页上可以看本机会话、接着说、停止、答征询、改权限模式。网络恢复后可以从这页重连，回到中枢 `/code` 的同一会话。
  - 富文本画法在构建时从控制台的 `CODE_RENDER_JS` 拷入，与在线页一致。

### Work（P37.17）

- **常驻会话**（#290）：每个账号跟每个智能体只有一条常驻会话，侧栏顶部智能体一区的每一行就是它。以前的会话收进这一行 ⋯ 菜单的「其他对话」，只读。
- **开始一项工作**（#288 节点与接口，#290 界面）：
  - 入口：侧栏「开始一项工作」打开新工作页。
  - 工作流：演示文稿、文档、表格、调研报告、网页、数据分析，共六个。它们是自写技能，随节点下发。
  - 执行者：缺省是主智能体，可以在「由谁来做」里换人。
  - 产出：节点的文档宿主工具按描述生成 pptx、docx、xlsx 与无脚本的 HTML 预览；PDF 要看节点上有没有浏览器。交付的文件在对话里出文件卡，中枢 `/v0/work/*` 负责列出、预览与下载。
  - 进度：工作会话有活动面板，显示进度与上下文。

### 分栏与侧栏（P37.18）

- **分栏与悬停侧栏**（#295）：
  - 分栏：同一窗口最多四栏并排，一列可以上下分两格。从侧栏拖会话，或在 ⋯ 菜单里开分栏。快捷键 ⌃⌘\ ⌃⌘- ⌃] ⌃[ ⌃⌘W。布局按设备记住，四栏共用窗口的一条事件流。
  - 侧栏：可以收起（⌘B），收起后悬停侧栏按钮会浮出，移开就收回。
  - 浏览器 `/`、桌面 `/app` 与 Code 页的做法一致。

### 权限模式（P39）

- **中枢默认档**（#278）：
  - 参数：`--elevation-default <off|accept-edits|auto|full-access>`，开了 `--elevation` 时缺省 `auto`。
  - 行为：中枢每 60 秒核对一次各节点，把处在人工确认、能生效、没被人关掉的智能体开成默认档，一次 24 小时、2000 次。到期、用尽或节点重启后再开。
  - 人的选择优先：有人手动选「人工确认」或收回的，中枢记下，不再自动开。
  - 记录：开启的主体是 `system:elevation`，动作账本与节点审计链都有记录。设计见 [`elevation.md`](./elevation.md) §8.1。

### 性能（#296）

客户端卡顿查到以下几处，改后的数字都在本机 Chromium 的性能跟踪里测得，没有在 Qmo.app 的 WebKit 里测过：

| 场景 | 原因与改法 | 改前 | 改后 |
|---|---|---|---|
| Code 页流式输出（回放 400 段增量） | 富文本改成增量画，步骤组的标签不再每次重算 | 主线程占用 77%，长任务 111 个 | 26%，0 个 |
| 行的 ⋯ 菜单打开时 | 样式规则 `:has(:popover-open)` 会让整页重算样式，改成菜单开合时切一个类 | 每帧重算 1,653 个元素 | 6 个 |
| `/app` 打开一条 274 条记录的会话 | 片段没变就不重画；转录按服务端标记就地合并，不整段替换；换会话时的轮询推后 150 ms 合并 | 长任务 11 个（987 ms） | 1 个（66 ms） |
| 事件流断开后的 60 秒 | 重连改为退避，5 秒起，翻倍到 60 秒 | 主线程 4.9 s | 2.0 s |
| 四栏空闲 | 分栏里的待批准轮询改由窗口统一做，再分给各栏 | 每分钟 80 个请求 | 32 个 |
| 输入框每按一个键 | 自动增高少一次强制布局 | 7.0 ms | 6.1 ms |

## 升级注意

- **开着 `--elevation` 的中枢**：
  - 升级后缺省 `--elevation-default auto`。第一次部署时还没有记录文件，此前处在人工确认的智能体都会被开成自动审批。要保持原来的行为，启动参数加 `--elevation-default off`。
  - 回滚到本版之前的版本时，旧版重放动作账本会把 `system:elevation` 的行判为损坏，并停掉记账写操作。回滚前先把这些行移出 `actions.ndjson`，或者连账本文件一起回滚。
- **对话**：升级后，每个人跟每个智能体只有一条常驻会话，第一句话时开出。以前的会话在智能体那一行 ⋯ 的「其他对话」里，只读，不能接着说。
- **后台入口**：主页面上没有「管理后台」链接了，入口在侧栏底部的「设置」，也可以按 ⌘, 或 Ctrl+,。
- **Work**：中枢与节点都要升级。六个工作流技能和文档宿主工具在节点上。外部底层（Claude Code、Codex、ACP）不会收到这六个技能。旧版控制台读新的对话记录时，文件卡退化成一条过程行，活动记录整行跳过；这一点只按代码核对过，没有起旧版本跑。
- **桌面版**：Code 本机会话、Remote 与离线 Code 都要用新的 Qmo.app，运行器在随包的 `qmo` 里。本版不附安装包，要在 macOS 上自己构建：`bun run atlas:build:app`，见 [`atlas/apps/qmo/README.md`](../../atlas/apps/qmo/README.md)。
- **Remote**：只给个人账号。旧式令牌与 break-glass 访问 `/v0/code/*` 一律 403；中枢没接设备账本时，`/v0/client/link` 与 `/v0/code/*` 是 404 或 501。
- **构建与开发**：
  - 工具链升到 Bun 1.4.4（`.tool-versions`）。换了基座，原生插件要重编：`bun run build:native`。
  - 新基座里，`--model`、设置、角色与任务智能体里带厂商前缀的模型选择要写确切的模型 ID 或别名，写近似的名字会报错并给出候选，不再自动选上相近的模型（上游 v18.14.0）。不带前缀的写法（如 `opus`）仍按模糊匹配。
