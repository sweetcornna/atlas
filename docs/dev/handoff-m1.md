## §1 场景与验收判据

| # | 场景 | 必须做到 |
|---|---|---|
| U-1 | **关机转交**：在 Claude Code / Codex / occ 里说「我要关机了，交给云端」 | 本地 agent 调 `qianmo_handoff`；最后一次同步落地后才回「可以关机」 |
| U-2 | **云端续跑** | 中枢派给节点；执行者带着原会话上下文继续，不重新问背景 |
| U-3 | **远程直连**：`qm attach <task>` | 看到节点上正在跑的真实 CLI 界面，可以直接打字接管 |
| U-4 | **接回**：`qm pull <task>` 或对 agent 说「接回来」 | 本地没动过就快进；动过就另开分支，不覆盖本地改动 |

| 编号 | 判据 |
|---|---|
| **AC-H1 安全关机** | 回「可以关机」时，中枢的影子提交树哈希 = 本地工作区（含未跟踪、未忽略文件）树哈希，会话记录偏移 = 本地文件大小 |
| **AC-H2 上下文续接** | 沿用 AC-1 的方法：本地会话里推出的上下文事实，云端首条相关回答能命中 |
| **AC-H3 三入口** | 同一用例从 Claude Code、Codex、occ 发起都通过 AC-H1、AC-H2 |
| **AC-H4 远程直连** | 从另一台机器 attach 到节点上运行中的真实 CLI，输入被执行 |
| **AC-H5 接回不覆盖** | 本地未改 → 快进；本地有改 → 另开分支，本地文件逐字节不变 |

节点网络（AC-2、AC-3）靠现有回归用例保证不回归，不另立判据。

## §4 互通面

对方工具零改动，只用它们的公开扩展点。

**`qm mcp`**（stdio MCP server）只暴露以下工具：

| 工具 | 作用 |
|---|---|
| `qianmo_status` | 同步状态，是否可以安全关机 |
| `qianmo_handoff` | 宿主 agent 写接力简报（目标、已完成、剩余），工具冲刷同步、核对落地、登记任务 |
| `qianmo_task` | 查接力任务状态与最近输出 |
| `qianmo_pull` | 接回 |
| `qianmo_send` | 向 `qianmo://<node>/<agent>` 发任务消息（节点互通） |

接入：Claude Code 用 `claude mcp add` 注册，外加 `/handoff`、`/pullback` 两个命令和会话结束 hook 调 `qm sync --flush`；Codex 在 MCP 配置里注册，回合结束通知钩子调 `qm sync --flush`；occ 内建。具体命令按当时版本在 P17.2 实测后写进用户文档。

对 `~/.claude`、`~/.codex` 只读；默认不往里写。凭据从不随同步或接力移动。

## §5 同步

| 对象 | 方式 | 时机 |
|---|---|---|
| 代码与未提交改动 | 用临时 index 做影子提交，推到中枢 `refs/qianmo/wip/<设备>/<分支>`；不动用户的 HEAD、index、stash | 文件变更去抖后；回合结束；转交时强制 |
| 会话记录 | JSONL 按字节偏移增量上传 | 同上 |
| 项目记忆 | `CLAUDE.md` / `AGENTS.md` 随代码走 | — |

- 按项目开启：`qm sync enable`。
- 排除 `.gitignore` 命中项、`.env*`、密钥类文件；推前做一次秘密扫描（复用 `occ migrate` 的凭据规则），命中就拒推并在 `qianmo_status` 里报出。
- 落地核对：代码比树哈希，会话比偏移。云端只写 `qianmo/<task>` 分支，不碰用户分支。

## §6 接力

**接力清单**：`taskId`、发起工具与会话 id、本地 cwd、影子提交、会话记录偏移、简报、执行者（默认 occ）、截止时间。

**状态**：`accepted`（此刻回「可以关机」）→ `running` → `done` / `failed` → `returned`。回「可以关机」只取决于数据是否落地，不等派发；派发失败由中枢重试。

**派发**：走现有 `task.request`，回执、重投、去重、防环、限流全部沿用。选节点：满足执行者要求的在线节点里挑一个空闲的。

## §7 执行者、直连、接回

**occ（默认）**：节点从同步仓 clone、检出影子提交、建 `qianmo/<task>` 分支；导入会话记录并重映射 cwd 后 `loadSession` 续上。导入失败就用「简报 + 最近几轮」开新会话，并在通知里说明。

**真实 Claude Code / Codex CLI**：节点上装好 CLI，用户先 `qm attach` 进去自己登录一次。节点用 tmux 托管 CLI 界面，把会话记录放进节点自己的状态目录后用该工具的恢复入口启动，首条输入是简报；hook 调 `qm task report` 回报。

**远程直连**：`qm attach <task>` = 经 SSH 进节点 `tmux attach`。断开不杀进程。

**接回**：取回 `qianmo/<task>` 与接回简报；本地没动过就快进，动过就另建 `qianmo/<task>-return` 分支并报差异。

## §8 安全

- 接力是用户本人发起的授权，范围限于该项目、`qianmo/` 前缀分支、截止时间内。云端不推默认分支、不打标签、不发布、不付款；遇到这类动作停下来通知用户。P14 授权流落地后接上即可，不作为开工前置。
- 执行在节点沙箱（Dormice + gVisor）内。
- 转交、派发、直连、接回写 `@qianmo/audit`。
- 新路径经 `src/config/paths.ts` 派生；不动品牌/协议字符串（章程 §5.2③）。对外说「与 Claude Code、Codex 互通」按章程 §5.8 办。
