## §0 现状

- `qmo`（P37.1）在系统 Chromium 内核浏览器的应用窗口里打开 `/`，没有原生窗口、托盘、全局快捷键和系统通知。
- `/` 已按 Grok Bot 的形制做成智能体列表加气泡对话（#253 前台重做），右侧面板按 Claude Desktop 的样子放后台任务和云端电脑。
- 代码里 `desktop` 指 P21 云端电脑。桌面版的代码叫 `app`（中枢路由 `/app`、壳 `atlas/apps/qmo`），不叫 desktop。
- 参照材料不进仓库：Claude Desktop 3.1623.1 的 REA 静态分析与 Grok Bot 的公开页面摘要放在负责人本机的证据目录。本文只写我们自己的取舍和数值，不复制对方的代码、文案、图标和品牌。

## §1 产品形态

一个应用，一个主窗口，两种界面，外加一个快速输入窗：

| 界面 | 地址 | 形制 | 适合 |
|---|---|---|---|
| 对话 | `/app` | Claude Desktop：左侧是「新对话」和按时间分组的最近对话，主区是居中的阅读栏，空白时问候语下面是大输入框 | 跟一个智能体做一件事，读长回答 |
| 智能体 | `/` | Grok Bot：左侧是智能体名册，每个智能体一条线程，头像动作表示进度，气泡对话 | 同时看几个智能体在做什么，给子智能体派活 |
| 快速输入 | `/app/quick` | 浮在桌面最上层的一条输入框，全局快捷键唤出 | 不切窗口，随手交代一件事 |

两种界面共用侧栏骨架（宽度、顶部、底部账号行）、配色与主题色、头像、字体、圆角、输入框、步骤折叠、审批卡片和右侧面板。侧栏顶部是同一个切换控件「对话 · 智能体」，位置和尺寸在两边完全一致，切换读起来像换标签页。

浏览器里照样能用：`/app` 和 `/` 对任何能用前台的人开放，桌面版只是默认打开 `/app`。

## §2 架构

```
┌──────────── Qmo.app（Tauri v2，Rust）────────────┐
│ 主窗口 WebView ── https://<中枢>/app、/            │
│ 快速输入 WebView ── https://<中枢>/app/quick       │
│ 本地页面 ── 登录、离线、设置、关于（随壳打包）     │
│ 菜单 · 托盘 · 全局快捷键 · 通知 · 角标 · 单实例   │
│ qmo（随壳打包的 sidecar）── 设备令牌、票据、进门   │
└──────────────────────────────────────────────────┘
```

- 壳用 Tauri v2（macOS WKWebView、Windows WebView2、Linux WebKitGTK），就是 clients.md 规划的 P37.8 原生窗口。选它不选 Electron：不打包浏览器内核，安装包小；仓库已有 Rust 工具链；系统集成（托盘、快捷键、通知、单实例、深链、开机启动、窗口状态）都有官方插件。
- 界面不随壳打包，由中枢渲染。这和 Claude Desktop 装载网页版是同一个思路，好处是界面和中枢一起升级、浏览器与桌面版一致、中枢的 CSP、角色、语言、主题照常生效。控制台「服务端渲染、零依赖」的约束（章程 N-5）不变。
- 凭据只在 `qmo` 里。壳不读设备令牌，只通过管道向 `qmo` 要一次会话 cookie。

## §3 登录与进门

1. 首次打开显示本地登录页：中枢地址、配对码两栏，下方一行说明配对码在中枢「连接 › 本机工具 › 添加设备」里拿。提交后壳运行 `qmo sign-in <地址> --name <主机名>`，配对码从标准输入送进去，不上命令行。
2. 打开中枢时壳运行 `qmo session --json`。`qmo` 换一张票据，自己带 `X-Qmo-Device` 和 `Sec-Fetch-Site: none` 请求 `/client/enter`，不跟随 303，把响应里的会话 cookie 与客户端 cookie 原样（名字、值、Path、Secure、HttpOnly、SameSite、Max-Age）写到标准输出的 JSON 里，再按 clients.md §3.2 第 5 步核对票据已用掉。这与 Linux 管道路线等价：头由客户端进程加，网页加不了。
3. 壳把 cookie 写进 WebView 的 cookie 库，再加一枚 `qianmo_shell=<macos|windows|linux>`（非 HttpOnly，供服务端渲染壳专属的边距），然后打开 `/app`。从本地页面（`tauri://localhost`）或别的中枢跳过去时，WebKit 把这次导航当作跨站，不带 `SameSite=Strict` 的会话 cookie，中枢会把人打回 `/login`；所以壳先载入 `about:blank`、写进骨架，再从那里打开中枢。这是实测到的 WebKit 行为，不是文档承诺，WebKitGTK 上还没验证。快速输入窗换中枢时直接重建。
4. 页面导航到 `/login`（会话过期、在别处退出）时，壳拦下，重走第 2 步后回到原地址；`qmo` 报设备已吊销时回到登录页。
5. 退出登录在壳里是吊销这台设备：页面账号菜单的「退出登录」在桌面版里调用壳的 `qmo_sign_out`，壳运行 `qmo sign-out`、清掉 WebView 的 cookie，回到登录页。只在网页上退出没有意义，壳会马上重新进门。
6. 中枢没开个人账号（`/v0/client/tickets` 为 404）时，壳直接打开 `/login`，由人贴凭据，和 `qmo open` 一致。

## §4 界面

### 4.1 对话（`/app`）

- **侧栏**：顶部是品牌标与收起按钮（macOS 上为红绿灯留出左边距）；下面是「对话 · 智能体」切换；「新对话」一行（⌘N）；「搜索」一行（⌘K，搜对话标题与智能体名）；然后是最近对话，分「今天 / 昨天 / 过去 7 天 / 更早」。一行是对话标题，非主智能体的对话前面有它的小头像；执行中显示进度点，有未读显示圆点；悬停出现「⋯」，里面是现有前台对会话支持的操作。底部是账号行，菜单与 `/` 相同（外观、主题色、语言、后台、退出登录）。
- **顶栏**：对话标题、智能体标签（头像、名字、节点、模型），右侧是右侧面板开关。空白新对话时只留面板开关。整条顶栏在桌面版里可拖动窗口。
- **新对话**：阅读栏中部是问候语（按时段，「下午好」之类，附主智能体头像），下面是大输入框。输入框底部一行：`+`（命令）、智能体选择（默认主智能体，可选名册里任何一个，选中即决定新对话发给谁）、现有的模型与权限选择、语音、发送。不放建议问题。
- **对话**：阅读栏居中。人的消息是右侧的浅色圆角块（中性底色，不用主题色）；智能体的回答不加气泡，正文直接排在阅读栏里，段首是智能体的小头像和名字（同一智能体连续回答只出现一次）。悬停回答出现复制。过程步骤折叠成一行「已执行 · N 步」，展开是现有的步骤清单。等待中用现有的八类活动动画和原地换词。审批卡片、投递状态、时间分隔照旧。
- **右侧面板**：与 `/` 相同（后台任务、云端电脑）。

### 4.2 智能体（`/`）

形制不变，只做统一：

- 侧栏顶部换成与 `/app` 一致的骨架：品牌标、收起、「对话 · 智能体」切换、「新对话」一行（在这里是给当前智能体开新会话）、搜索。
- 侧栏宽度、行高、圆角、字号、底部账号行与 `/app` 取同一组变量。
- 顶栏可拖动、壳边距与 `/app` 相同。
- 照 Grok Bot：执行中的智能体头像在动、悬停行显示当前动作（已有的活动摘要），未读点；云端电脑在用时顶栏面板按钮旁有一个主题色小点（状态），点开右侧面板就是预览。

### 4.3 快速输入（`/app/quick`）

- 一张浮动卡片（约 606 px 宽，16 px 圆角）：左边主智能体头像（点开可换智能体），中间一行输入框（可长到四行），右边发送。页面背景透明，卡片有阴影和圆角。
- 回车发送：用现有聊天接口开会话、发消息，然后调用壳的 `qmo_open_session`，主窗口显示并打开这条对话，快速输入窗隐藏。不在壳里时跳到 `/app?session=<id>`。
- Esc、失焦都会隐藏；再次唤出时清空。

### 4.4 共同要求

- 中文、英文、日文全部文案；明暗两套配色都过 WCAG AA；窗口宽度 ≤ 700 px 时侧栏改抽屉；`prefers-reduced-motion` 时动画只留透明度变化。
- 加载、空、失败、离线、只读角色五种状态都有呈现；网络断开时顶部出现一条细提示，恢复后自动消失。
- 键盘：⌘N 新对话，⌘K 搜索，⌘⇧S 收起侧栏，⌘. 打开右侧面板，Esc 关闭弹层；Windows 与 Linux 用 Ctrl。快捷键说明在键盘帮助里。
- 文案遵守前台语气定案：冷静、精简，只留标签和状态。

### 4.5 视觉数值

见 §10 参照表；实现以 `assets/css.ts` 里 `:root` 的变量为准，前台与后台同一组，不各写一套（实际取值见 [`qmo-local.md`](./qmo-local.md) §3.4）。

## §5 壳与页面的约定

页面是中枢的，壳是本机的。两边只经下面这些接口说话，别的都不通。

### 5.1 壳告诉页面

- cookie `qianmo_shell`：`macos`、`windows` 或 `linux`。中枢据此在 `<html>` 上渲染 `data-shell`，页面按它加红绿灯边距和拖动区，不闪。浏览器里没有这枚 cookie，什么都不变。
- 注入脚本在页面脚本之前设 `window.__QMO_SHELL__ = { platform, window: 'main' | 'quick', version }`。页面靠它决定是否调用壳的命令。
- 拖动区：页面在顶栏与侧栏顶部写 `data-tauri-drag-region`；浏览器里这个属性没有作用。后台各页（`/admin/*`）同样：侧栏品牌行与顶栏可拖动，macOS 上品牌行从 80 px 起，窄窗口下顶栏也让开红绿灯。

### 5.2 页面请壳做的事

经 Tauri IPC（`window.__TAURI__.core.invoke`）调用。只有中枢源与本地页面能调；参数在 Rust 里逐项校验，超长、类型不对、越界一律拒绝。P37.13 加的后三条另在命令里核一次调用方页面与登录的中枢同源，本地页面和别的源调用都拒绝。

| 命令 | 参数 | 作用 |
|---|---|---|
| `qmo_shell_info` | 无 | 返回 `{ platform, version, quickShortcut }`，页面用它在键盘帮助里写快速输入的快捷键 |
| `qmo_notify` | `title` ≤ 120 字，`body` ≤ 300 字，`session?` | 主窗口不在前台时发系统通知；点通知回到主窗口并打开该对话 |
| `qmo_badge` | `count` 0–999 | 程序坞或任务栏角标，0 清除 |
| `qmo_open_session` | `session`（`[A-Za-z0-9_-]{1,128}`） | 显示并聚焦主窗口，打开 `/app?session=<id>`，隐藏快速输入窗 |
| `qmo_quick_hide` | 无 | 隐藏快速输入窗 |
| `qmo_sign_out` | 无 | 吊销这台设备、清 cookie、回到登录页 |
| `qmo_local_agents` | `rescan?`（布尔，缺省 false） | 跑随包的 `qmo agents --json`（`rescan` 时加 `--rescan`），返回 `{ agents: [...] }`，每项原样是 [`qmo-local.md`](./qmo-local.md) §4.2 的字段。30 秒超时；同一时刻只跑一个，后到的调用等正在跑的那次的结果（正在跑的不是 rescan 而后到的是时，等它结束再跑一次 rescan）。失败时 Promise 以一行说明拒绝 |
| `qmo_boot_layout` | `layout`：`page`（`chat` \| `agents` \| `code`）、`side`（`open` \| `closed`）、`sideWidth` 0–1000、`rows` 0–60、`labels` 0–20 的整数，`theme?`（`system` \| `light` \| `dark`，缺省 `system`），`colors?`（`{ dark, page, sidebar }`，两色都是 `#rrggbb`） | 记下页面的布局与颜色，下次骨架页按它画（[`qmo-local.md`](./qmo-local.md) §3.5）；颜色按 `dark` 分浅、深两套存，没带 `colors` 时不动已存的 |
| `qmo_open_local_settings` | 无 | 打开壳自己的设置窗（同菜单「设置」），给页面设置卡片里的「桌面版」一项用 |

页面什么时候发：智能体回复了一条不在眼前的对话（窗口不在前台或打开的是别的对话）时 `qmo_notify`；未读数变化时 `qmo_badge`。

### 5.3 壳替页面做的事

- 主窗口只在中枢源和本地页面之间导航；其他地址一律交给系统浏览器打开，新窗口请求同样处理。
- 中枢页面载入完成之前，主窗口先显示本地骨架页，不出现白屏：窗口建好就是页面底色，骨架按页面上次经 `qmo_boot_layout` 报的布局与颜色画（侧栏宽或收起、Work \| Code 里上次的面、行数与分组标题数，见 [`qmo-local.md`](./qmo-local.md) §3.5；没报过时是 288 px 侧栏加空白阅读栏），明暗随系统；中枢连不上时换成离线页，带重试。
- 菜单与托盘的「新对话」让主窗口打开 `/app`；深链 `qmo://session/<id>` 打开 `/app?session=<id>`，`qmo://new` 打开 `/app`。

## §7 安全边界

- 设备令牌只在 `qmo` 进程与它的状态文件里，壳与 WebView 都拿不到。壳只经管道收一次会话 cookie，用完即丢，不落盘（WebView 自己的 cookie 库除外，与浏览器保存登录状态是同一条边界）。
- IPC 只对中枢源开放：运行时按登录时的中枢地址加一条 remote 能力，只含 §5.2 的九个命令；不开放文件系统、shell、HTTP 等插件给网页。`qmo_local_agents` 只让页面拿到 `qmo agents` 的识别结果（只 stat、查 PATH、跑 `--version`，不以服务或协议模式启动任何 agent），页面不能传路径、命令或别的参数。
- 导航白名单是中枢源；其他地址交系统浏览器。正式版关闭开发者工具。
- 本地页面的 CSP 只允许自身脚本与样式；中枢页面的 CSP 不因壳改变。
- `qianmo_shell` 只影响边距与拖动区，服务端只接受三个枚举值。

## §8 构建

- 壳在 `atlas/apps/qmo/`：`src-tauri/`（Rust，自成 Cargo 工作区，不并入根工作区）与 `ui/`（本地页面，纯 HTML/CSS/JS）。
- `bun run atlas:build:app` 先用 `atlas:build:client` 的办法编出本机目标的 `qmo` 放进 `src-tauri/binaries/qmo-<目标三元组>`，再 `cargo tauri build`。开发时 `bun run atlas:dev:app`。
- 与 `qmo` 同一条规矩：各系统的安装包在本系统上构建。macOS 版的 `qmo` 只能在 macOS 上编；`qmo` 不用 WebSocket，不受 macOS 构建内联 ws 的问题影响。
- 图标由阡陌标生成（`cargo tauri icon`）。
- 安装包：macOS 在本机用 `hdiutil` 把 `Qmo.app` 与 `Applications` 快捷方式压成 `.dmg`（做法见 `atlas/apps/qmo/README.md`「打包」）。`tauri.conf.json` 的 `signingIdentity` 为 `-`（整包 ad-hoc 签名，资源封印）、`hardenedRuntime` 为 `false`（没有公证它没有用，随包的 `qmo` 是 Bun 编译产物，开着要另给 JIT 授权）；有 Developer ID 时用 `APPLE_SIGNING_IDENTITY` 覆盖。Rust 依赖的许可声明由 cargo-about 生成到 `src-tauri/THIRD-PARTY-NOTICES.txt`，随 `.app` 放进 `Resources/`。
- Developer ID 签名、公证、自动更新不在本轮（P37.9）。
