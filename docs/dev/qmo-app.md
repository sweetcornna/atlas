## §0 现状

- `qmo`（P37.1）在系统 Chromium 内核浏览器的应用窗口里打开 `/`，没有原生窗口、托盘、全局快捷键和系统通知。
- `/` 已按 Grok Bot 的形制做成智能体列表加气泡对话（#253 前台重做），右侧面板按 Claude Desktop 的样子放后台任务和云端电脑。
- 代码里 `desktop` 指 P21 云端电脑。桌面版的代码叫 `app`（中枢路由 `/app`、壳 `atlas/apps/qmo`），不叫 desktop。
- 参照材料不进仓库：Claude Desktop 3.1623.1 的 REA 静态分析与 Grok Bot 的公开页面摘要放在负责人本机的证据目录。本文只写我们自己的取舍和数值，不复制对方的代码、文案、图标和品牌。

## §1 产品形态

一个应用，一个主窗口，两种界面，外加一个快速输入窗：

| 界面 | 地址 | 形制 | 适合 |
|---|---|---|---|
| 对话 | `/app` | Claude Desktop：左侧是「开始一项工作」、智能体一区和按日期分组的工作，主区是居中的阅读栏，空白时问候语下面是大输入框 | 跟一个智能体做一件事、开始一项工作，读长回答 |
| 智能体 | `/` | Grok Bot：左侧是智能体名册，每个智能体一条线程，头像动作表示进度，气泡对话 | 同时看几个智能体在做什么，给子智能体派活 |
| 快速输入 | `/app/quick` | 浮在桌面最上层的一条输入框，全局快捷键唤出 | 不切窗口，随手交代一件事 |

两种界面共用侧栏骨架（宽度、顶部、底部账号行）、配色与主题色、头像、字体、圆角、输入框、步骤折叠、审批卡片和右侧面板。侧栏顶部是同一个切换控件「对话 · 智能体」，位置和尺寸在两边完全一致，切换读起来像换标签页。

浏览器里照样能用：`/app` 和 `/` 对任何能用前台的人开放，桌面版只是默认打开 `/app`。

## §2 架构

```
┌──────────── Qmo.app（Tauri v2，Rust）────────────┐
│ 主窗口 WebView ── https://<中枢>/app、/            │
│ 快速输入 WebView ── https://<中枢>/app/quick       │
│ 本地页面 ── 登录、离线、设置、关于（随壳打包）     │
│ 菜单 · 托盘 · 全局快捷键 · 通知 · 角标 · 单实例   │
│ qmo（随壳打包的 sidecar）── 设备令牌、票据、进门   │
│   └ qmo code serve ── 本机会话的运行器（常驻）     │
└──────────────────────────────────────────────────┘
```

- 壳用 Tauri v2（macOS WKWebView、Windows WebView2、Linux WebKitGTK），就是 clients.md 规划的 P37.8 原生窗口。选它不选 Electron：不打包浏览器内核，安装包小；仓库已有 Rust 工具链；系统集成（托盘、快捷键、通知、单实例、深链、开机启动、窗口状态）都有官方插件。
- 界面不随壳打包，由中枢渲染。这和 Claude Desktop 装载网页版是同一个思路，好处是界面和中枢一起升级、浏览器与桌面版一致、中枢的 CSP、角色、语言、主题照常生效。控制台「服务端渲染、零依赖」的约束（章程 N-5）不变。
- 凭据只在 `qmo` 里。壳不读设备令牌，只通过管道向 `qmo` 要一次会话 cookie。
- 本机会话（P37.14）也由随包的 `qmo` 驱动：壳在页面第一次调本机会话的命令时起 `qmo code serve`，经标准输入输出说话，把它的事件转进主窗口页面登记的通道；不带 `qm`，不开端口（[`qmo-local.md`](./qmo-local.md) §4.3、§4.5）。

## §3 登录与进门

1. 首次打开显示本地登录页：中枢地址、配对码两栏，下方一行说明配对码在中枢「连接 › 本机工具 › 添加设备」里拿。提交后壳运行 `qmo sign-in <地址> --name <主机名>`，配对码从标准输入送进去，不上命令行。
2. 打开中枢时壳运行 `qmo session --json`。`qmo` 换一张票据，自己带 `X-Qmo-Device` 和 `Sec-Fetch-Site: none` 请求 `/client/enter`，不跟随 303，把响应里的会话 cookie 与客户端 cookie 原样（名字、值、Path、Secure、HttpOnly、SameSite、Max-Age）写到标准输出的 JSON 里，再按 clients.md §3.2 第 5 步核对票据已用掉。这与 Linux 管道路线等价：头由客户端进程加，网页加不了。
3. 壳把 cookie 写进 WebView 的 cookie 库，再加一枚 `qianmo_shell=<macos|windows|linux>`（非 HttpOnly，供服务端渲染壳专属的边距），然后打开 `/app`。从本地页面（`tauri://localhost`）或别的中枢跳过去时，WebKit 把这次导航当作跨站，不带 `SameSite=Strict` 的会话 cookie，中枢会把人打回 `/login`；所以壳先载入 `about:blank`、写进骨架，再从那里打开中枢。这是实测到的 WebKit 行为，不是文档承诺，WebKitGTK 上还没验证。快速输入窗换中枢时直接重建。
4. 页面导航到 `/login`（会话过期、在别处退出）时，壳拦下，重走第 2 步后回到原地址；`qmo` 报设备已吊销时回到登录页。
5. 退出登录在壳里是吊销这台设备：页面账号菜单的「退出登录」在桌面版里调用壳的 `qmo_sign_out`，壳运行 `qmo sign-out`、清掉 WebView 的 cookie，回到登录页。只在网页上退出没有意义，壳会马上重新进门。
6. 中枢没开个人账号（`/v0/client/tickets` 为 404）时，壳直接打开 `/login`，由人贴凭据，和 `qmo open` 一致。

## §4 界面

### 4.1 对话（`/app`）

- **侧栏**：顶部是品牌标与收起按钮（macOS 上为红绿灯留出左边距）；下面是「对话 · 智能体」切换；「搜索」一行（⌘K，搜智能体名与对话标题）；然后是智能体一区（P37.17 A，定案与理由见 [`console.md`](./console.md) §6.1「常驻会话」）：读者能对话的每个智能体一行，主智能体第一，其余按最近活动，一行就是这个人跟它的那一条常驻会话。行上是头像（右下角在线点）、名字、主智能体的「主」、最近活动时间、第二行最后一句或「处理中」、未读圆点；悬停出现「⋯」：其他对话（带条数）、换形象、复制地址，运维还有节点详情与模型设置。「搜索」上方是「开始一项工作」一行（⌘N）。再下面按「今天 / 昨天 / 过去 7 天 / 更早」分组的列表放这个人的工作会话（P37.17 B 的广泛性工作，[`work-tasks.md`](./work-tasks.md) §9.1–9.2）：工作流图标、标题、进行中 / 等你 / 完成三种状态记号、未读点；没有时不画。底部是账号行，菜单与 `/` 相同（外观、主题色、语言、后台、退出登录）。
- **顶栏**：智能体标签（头像、名字、节点、模型），打开的不是常驻会话时前面还有对话标题；右侧是右侧面板开关。欢迎页只留面板开关。整条顶栏在桌面版里可拖动窗口。
- **欢迎页**：一个智能体还没有常驻会话时，阅读栏中部是问候语（按时段，「下午好」之类，附它的头像），下面是大输入框，第一句话开出常驻会话。输入框底部一行：`+`（命令）、智能体选择（默认主智能体，可选名册里任何一个，选中就切到那个智能体）、现有的模型与权限选择、语音、发送。不放建议问题。
- **对话**：阅读栏居中。人的消息是右侧的浅色圆角块（中性底色，不用主题色）；智能体的回答不加气泡，正文直接排在阅读栏里，段首是智能体的小头像和名字（同一智能体连续回答只出现一次）。悬停回答出现复制。过程步骤折叠成一行「已执行 · N 步」，展开是现有的步骤清单。等待中用现有的八类活动动画和原地换词。审批卡片、投递状态、时间分隔照旧。
- **开始一项工作**：`/app?work=new`，标题下一排六张工作流卡片（演示文稿、文档、表格、调研报告、网页、数据分析）和大输入框；点卡片或在输入框里打 `/` 选工作流，「由谁来做」缺省主智能体；第一句话开出工作会话（[`work-tasks.md`](./work-tasks.md) §9.3）。工作会话里智能体交付的文件是文件卡，可预览（不跑脚本的沙箱框）与下载（§9.4、§9.6）。
- **其他对话**：智能体 ⋯ 里的「其他对话」是一个对话框（这个智能体 / 全部），列这个人跟智能体的其他会话（部署常驻会话之前的旧会话，运维还能看到别人的）。点一条在阅读栏里只读打开：没有输入框，底部是「只读」与「回到 <智能体>」。
- **右侧面板**：与 `/` 相同（后台任务、云端电脑）；工作会话里顶上还有进度、产出、上下文三块，宽窗口打开工作会话时面板自己打开（[`work-tasks.md`](./work-tasks.md) §9.5）。

### 4.2 智能体（`/`）

形制不变，只做统一：

- 侧栏顶部换成与 `/app` 一致的骨架：品牌标、收起、「对话 · 智能体」切换、搜索，下面是与 `/app` 同一个智能体一区（P37.17：每个智能体一条常驻会话，没有「新对话」一行，「其他对话」与只读同 §4.1）。
- 侧栏宽度、行高、圆角、字号、底部账号行与 `/app` 取同一组变量。
- 顶栏可拖动、壳边距与 `/app` 相同。
- 照 Grok Bot：执行中的智能体头像在动、悬停行显示当前动作（已有的活动摘要），未读点；云端电脑在用时顶栏面板按钮旁有一个主题色小点（状态），点开右侧面板就是预览。

### 4.3 快速输入（`/app/quick`）

- 一张浮动卡片（约 606 px 宽，16 px 圆角）：左边主智能体头像（点开可换智能体），中间一行输入框（可长到四行），右边发送。页面背景透明，卡片有阴影和圆角。
- 回车发送：经现有聊天接口发到卡片上那个智能体的常驻会话（没有才开出，P37.17），然后调用壳的 `qmo_open_session`，主窗口显示并打开这条对话，快速输入窗隐藏。不在壳里时跳到 `/app?session=<id>`。
- Esc、失焦都会隐藏；再次唤出时清空。

### 4.4 共同要求

- 中文、英文、日文全部文案；明暗两套配色都过 WCAG AA；窗口宽度 ≤ 700 px 时侧栏改抽屉；`prefers-reduced-motion` 时动画只留透明度变化。
- 加载、空、失败、离线、只读角色五种状态都有呈现；网络断开时顶部出现一条细提示，恢复后自动消失。
- 键盘：⌘N 开始一项工作（浏览器里是 ⌘⇧O，⌘N 留给浏览器），⌘K 搜索，⌘B 收起侧栏（原来的 ⌘⇧S 仍可用），⌘. 打开右侧面板，⌃⌘\ / ⌃⌘- 在右侧或下方新开分栏，⌃] / ⌃[ 换分栏，⌃⌘W 关分栏（§11.3），Esc 关闭弹层；Windows 与 Linux 上 ⌘ 换成 Ctrl，⌃⌘ 换成 Ctrl+Alt。快捷键说明在键盘帮助里。
- 文案遵守前台语气定案：冷静、精简，只留标签和状态。

### 4.5 视觉数值

见 §10 参照表；实现以 `assets/css.ts` 里 `:root` 的变量为准，前台与后台同一组，不各写一套（实际取值见 [`qmo-local.md`](./qmo-local.md) §3.4）。

## §5 壳与页面的约定

页面是中枢的，壳是本机的。两边只经下面这些接口说话，别的都不通。

### 5.1 壳告诉页面

- cookie `qianmo_shell`：`macos`、`windows` 或 `linux`。中枢据此在 `<html>` 上渲染 `data-shell`，页面按它加红绿灯边距和拖动区，不闪。浏览器里没有这枚 cookie，什么都不变。
- 注入脚本在页面脚本之前设 `window.__QMO_SHELL__ = { platform, window: 'main' | 'quick', version }`。页面靠它决定是否调用壳的命令。
- 拖动区：页面在顶栏与侧栏顶部写 `data-tauri-drag-region`；浏览器里这个属性没有作用。后台各页（`/admin/*`）同样：侧栏品牌行与顶栏可拖动，macOS 上品牌行从 80 px 起，窄窗口下顶栏也让开红绿灯。

### 5.2 页面请壳做的事

经 Tauri IPC（`window.__TAURI__.core.invoke`）调用。只有中枢源与本地页面能调；参数在 Rust 里逐项校验，超长、类型不对、越界一律拒绝。P37.13 加的三条（`qmo_local_agents`、`qmo_boot_layout`、`qmo_open_local_settings`）另在命令里核一次调用方页面与登录的中枢同源，本地页面和别的源调用都拒绝；P37.14a 加的十三条与 P37.14d 加的两条（改名、删除）本机会话命令（表末）同样核同源，并且只收主窗口（快速输入窗调用也拒绝），失败一律以 `qmo local <代码>: <说明>` 拒绝，规则见 [`qmo-local.md`](./qmo-local.md) §4.5。表里的「字」按 UTF-16 码元计（JavaScript 字符串的 `length`），与页面、运行器同一种算法；每条命令的键、可缺省的键与交给运行器的参数写在 `atlas/packages/console/test/browser/qmo-local-calls.json`，壳、页面、运行器三方的用例都核它。

| 命令 | 参数 | 作用 |
|---|---|---|
| `qmo_shell_info` | 无 | 返回 `{ platform, version, quickShortcut }`，页面用它在键盘帮助里写快速输入的快捷键 |
| `qmo_notify` | `title` ≤ 120 字，`body` ≤ 300 字，`session?` | 主窗口不在前台时发系统通知；点通知回到主窗口并打开该对话 |
| `qmo_badge` | `count` 0–999 | 程序坞或任务栏角标，0 清除。显示的数是页面报的这个数加上等你确认的本机会话数，至多 999（§6） |
| `qmo_open_session` | `session`（`[A-Za-z0-9_-]{1,128}`） | 显示并聚焦主窗口，打开 `/app?session=<id>`，隐藏快速输入窗 |
| `qmo_quick_hide` | 无 | 隐藏快速输入窗 |
| `qmo_sign_out` | 无 | 吊销这台设备、清 cookie、回到登录页 |
| `qmo_local_agents` | `rescan?`（布尔，缺省 false） | 跑随包的 `qmo agents --json`（`rescan` 时加 `--rescan`），返回 `{ agents: [...] }`，每项原样是 [`qmo-local.md`](./qmo-local.md) §4.2 的字段。30 秒超时；同一时刻只跑一个，后到的调用等正在跑的那次的结果（正在跑的不是 rescan 而后到的是时，等它结束再跑一次 rescan）。失败时 Promise 以一行说明拒绝 |
| `qmo_boot_layout` | `layout`：`page`（`chat` \| `agents` \| `code`）、`side`（`open` \| `closed`）、`sideWidth` 0–1000、`rows` 0–60、`labels` 0–20 的整数，`theme?`（`system` \| `light` \| `dark`，缺省 `system`），`colors?`（`{ dark, page, sidebar }`，两色都是 `#rrggbb`） | 记下页面的布局与颜色，下次骨架页按它画（[`qmo-local.md`](./qmo-local.md) §3.5）；颜色按 `dark` 分浅、深两套存，没带 `colors` 时不动已存的 |
| `qmo_open_local_settings` | 无 | 打开壳自己的设置窗，给页面设置卡片里的「桌面版」一项用；也是菜单「设置」在没有设置卡片的旧中枢页面上的回退（§6） |
| `qmo_local_list` | 无 | 本机会话：运行器的 `list`，`{v, features, folders, sessions}`，壳加上 `defaults: {mode, remote}`（设置窗「Code」一节，§6）；第一次调用时壳起运行器 `qmo code serve` |
| `qmo_local_watch` | `channel`（`__CHANNEL__:<数字>`，即 `window.__TAURI__.core.Channel`） | 登记本页的事件通道，再调换掉旧的；主窗口开始载入页面时壳丢掉它 |
| `qmo_local_pick_folder` | 无 | 弹系统文件夹选择框（同一时刻一个），取真实路径交给运行器 `folders.add`；取消答 `null` |
| `qmo_local_forget_folder` | `folder`（`[0-9a-f]{16}`） | 运行器 `folders.forget` |

### 5.3 壳替页面做的事

- 主窗口只在中枢源和本地页面之间导航；其他地址一律交给系统浏览器打开，新窗口请求同样处理。
- 中枢页面载入完成之前，主窗口先显示本地骨架页，不出现白屏：窗口建好就是页面底色，骨架按页面上次经 `qmo_boot_layout` 报的布局与颜色画（侧栏宽或收起、Work \| Code 里上次的面、行数与分组标题数，见 [`qmo-local.md`](./qmo-local.md) §3.5；没报过时是 288 px 侧栏加空白阅读栏），明暗随系统；中枢连不上时换成离线页，带重试。
- 菜单与托盘的「开始一项工作」（⌘N）让主窗口打开新工作页 `/app?work=new`；深链 `qmo://session/<id>` 打开 `/app?session=<id>`，`qmo://new` 打开 `/app?work=new`。跟智能体说话是点侧栏里它那一行，没有「新对话」（P37.17）。

本机会话的通知、角标与退出确认（P37.14d，`src-tauri/src/attention.rs`）：

- 壳旁听运行器的事件（页面登记的通道照旧收到同样的事件）。`session` 事件里一个本机会话从运行中或等你确认变成完成或失败（一轮结束），或变成等你确认（新的征询）时，发一条系统通知：标题是会话标题，正文是「<agent> · 完成 / 出错 / 等你确认」。被人中止（已中断）的不发；主窗口在前面并且页面登记了通道（Code 页开着）时不发。点开通知：主窗口正显示 `/code` 且有通道时壳发 `{v: 1, type: 'open', session}` 让页面打开它，否则主窗口导航到 `/code?session=<id>`。
- 角标 = 页面经 `qmo_badge` 报的数 + 等你确认的本机会话数，至多 999；会话删掉、运行器停下时那一份减掉。
- 退出 Qmo（菜单 ⌘Q、托盘「退出」，以及不留后台时关主窗口）：运行器起着就问它 `list`（至多 2 s，不为此起运行器），数运行中与等你确认的会话；问不到就用旁听记下的数。是 0 直接退出；否则系统对话框「退出阡陌？」「有 N 个会话在运行，退出会中止它们」，按钮「退出」「取消」，同一时刻只问一次。程序坞的「退出」、注销与关机不经过这条路（tao 不给拦截点），直接按 `qmo-local.md` §4.3.2 收尾。

菜单的「设置… ⌘,」与托盘的「设置」照 Claude Desktop：主窗口显示的是已登录中枢的页面时，壳把主窗口带到前台，在里面执行一段固定的脚本 `(window.__qmoOpenSettings||function(){window.__TAURI__.core.invoke('qmo_open_local_settings')})()`（不拼任何变量），打开页面里的设置卡片；旧中枢的页面没有 `window.__qmoOpenSettings` 时，这段脚本回退为调 `qmo_open_local_settings`，开壳自己的设置窗。主窗口在本地页（登录、离线、骨架）、`about:blank` 或不存在时，直接开壳的设置窗。

## §7 安全边界

- 设备令牌只在 `qmo` 进程与它的状态文件里，壳与 WebView 都拿不到。壳只经管道收一次会话 cookie，用完即丢，不落盘（WebView 自己的 cookie 库除外，与浏览器保存登录状态是同一条边界）。
- IPC 只对中枢源开放：运行时按登录时的中枢地址加一条 remote 能力，只含 §5.2 的二十四个命令；不开放文件系统、shell、HTTP、对话框等插件给网页（对话框插件只用它的 Rust 接口，它给页面加的脚本也去掉了）。本机会话的命令只收主窗口，页面传不了路径与命令行：路径只从系统选择框进来（[`qmo-local.md`](./qmo-local.md) §4.5.3）。`qmo_local_agents` 只让页面拿到 `qmo agents` 的识别结果（只 stat、查 PATH、跑 `--version`，不以服务或协议模式启动任何 agent），页面不能传路径、命令或别的参数。
- 导航白名单是中枢源；其他地址交系统浏览器。正式版关闭开发者工具。
- 本地页面的 CSP 只允许自身脚本与样式；中枢页面的 CSP 不因壳改变。
- `qianmo_shell` 只影响边距与拖动区，服务端只接受三个枚举值。

## §8 构建

- 壳在 `atlas/apps/qmo/`：`src-tauri/`（Rust，自成 Cargo 工作区，不并入根工作区）与 `ui/`（本地页面，纯 HTML/CSS/JS）。
- `bun run atlas:build:app` 先用 `atlas:build:client` 的办法编出本机目标的 `qmo` 放进 `src-tauri/binaries/qmo-<目标三元组>`，再 `cargo tauri build`。开发时 `bun run atlas:dev:app`。
- 与 `qmo` 同一条规矩：各系统的安装包在本系统上构建。macOS 版的 `qmo` 只能在 macOS 上编。`qmo` 的设备链路（P37.15）用 Bun 自带的 `WebSocket`，不引 `ws` 包，所以不受 macOS 构建内联纯 JS `ws` 致握手失败的问题影响；编出来的 macOS `qmo` 对本机中枢的握手与推送有用例与实测（[qmo-local.md](qmo-local.md) §5.5、§9）。
- 图标由阡陌标生成（`cargo tauri icon`）。
- 安装包：macOS 在本机用 `hdiutil` 把 `Qmo.app` 与 `Applications` 快捷方式压成 `.dmg`（做法见 `atlas/apps/qmo/README.md`「打包」）。`tauri.conf.json` 的 `signingIdentity` 为 `-`（整包 ad-hoc 签名，资源封印）、`hardenedRuntime` 为 `false`（没有公证它没有用，随包的 `qmo` 是 Bun 编译产物，开着要另给 JIT 授权）；有 Developer ID 时用 `APPLE_SIGNING_IDENTITY` 覆盖。Rust 依赖的许可声明由 cargo-about 生成到 `src-tauri/THIRD-PARTY-NOTICES.txt`，随 `.app` 放进 `Resources/`。
- Developer ID 签名、公证、自动更新不在本轮（P37.9）。

## §11 分栏与侧栏（P37.18）

依据：负责人 2026-10-26「qmo 应当可以做到类似于这种的多窗口排布，并且可以收起侧边栏，鼠标悬浮停顿在侧边栏按钮可唤出浮动侧边栏，鼠标离开侧边栏区域会收回侧边栏」，附 Claude Desktop Code 页的截图：同一个窗口里四列会话并排，最左一列上下两格，每格有自己的头部、对话流和输入框。参照它只取布局、数值和交互（§10.1 的侧栏 288、头部 48，REA 报告里的红绿灯留白 74 和分屏快捷键），代码、文案、图标、配色都是我们自己的。

### 11.1 结论

- **分栏是同源 iframe。**每格装一份「分栏文档」，就是现有的 `/`、`/app`、`/code` 加 `pane=1`。外层文档（下称窗口文档）管侧栏、格子、分隔线、焦点、快捷键和布局记忆；格子里照常是前台：转录、输入框、模型与权限、审批卡片、会话面板，Code 的本机会话与 Remote 副本。
- **一个窗口只有一条长连接。**分栏文档不开 `EventSource`，窗口文档的那条流转给各格；Code 的运行器事件也只有窗口文档登记的那一条通道，转给各格。
- **Work 与 Code 不混放。**两种模式各有一份布局，各记各的，切模式时各回各的（理由见 11.6）。
- **侧栏收起后可悬停浮出：**鼠标在左上角的侧栏按钮上停 300 ms 浮出，离开「按钮＋浮层」250 ms 后收回。

### 11.2 先核的三件事

**同源连接数。**

- 读代码：Work 文档有一条 `GET /v0/chat/stream`（SSE，[`console.md`](./console.md) §6.6）；Code 文档在开了 Remote 的个人账号下另有一条 `GET /v0/code/stream`（`assets/codeHub.ts`）；本机会话的事件走壳的 Tauri 通道，不占 HTTP 连接。其余都是短请求：片段、发送、审批每 5 秒一次、会话面板 5 秒或 30 秒一次。
- 实测（2026-10-26，Bun 1.4.3）：内测环境的 TLS 前置 `demo/env/beta/ops/console-tls-front.ts` 是 `Bun.serve` 加 `tls`，不协商 ALPN。curl 报 `server did not agree on a protocol`，openssl 报 `No ALPN negotiated`，浏览器只能走 HTTP/1.1。本机直连 `http://` 也是 HTTP/1.1。Chromium 与 WebKit 对同一来源的 HTTP/1.1 连接都是最多 6 条。
- 如果每格自己开流：4 格加窗口文档是 5 条长连接，Code 有 Remote 时再翻一倍，超过 6 条以后片段、发送、审批都要排队，排到某条流断开为止，看上去就是卡住。
- 做法：分栏文档里 `qianmoSplit.stream(url)` 拿到的是窗口文档那条流的转发，事件照旧是 `open`、`chat`、`code`、`error`。窗口文档的流断开转入轮询时，各格也转入自己的轮询（2.5 秒一次的短请求）。这样一个窗口只占 1 条长连接，Code 有 Remote 时 2 条，与分栏数无关，不必再限分栏数。分栏文档不刷新侧栏片段（侧栏藏着）；分栏时窗口文档不刷新自己藏起来的转录。

**嵌入方式：同源 iframe，不在同一文档里多实例化。**

- 多实例化的改造面：`FRONT_JS`（60,114 字）整份是单实例写法，状态在闭包变量里，元素按 id 取（`fx-thread`、`fx-text`、`fx-scroll` 等）；模型与权限、会话面板、工作会话、审批卡片四份脚本也按 id 取。`CODE_JS` 定案时 35,972 字，P37.14d 合入后 36,895，预算 37,000。改成多实例等于重写全部前台脚本，`CODE_JS` 也装不下。iframe 只要在 `FRONT_JS`、`FRONT_SHELL_JS` 与 `CODE_HUB_JS` 里各加几行钩子；`CODE_JS` 一行不改，运行器通道由窗口文档包一层 `__TAURI__.core` 转发（见下表）。分栏的代码单独成 `FRONT_SPLIT_JS`，预算 52,000，按哈希进 CSP。
- 只有分栏文档放开嵌入。答带 `pane=1` 的 Work 或 Code 文档时，CSP 的 `frame-ancestors` 换成 `'self'`，`X-Frame-Options` 换成 `SAMEORIGIN`。其余文档仍是 `'none'` 和 `DENY`，包括这些地址答出的登录页、错误页和设置卡片。所有文档的 `frame-src 'self'` 不变。窗口文档放进 iframe 的地址只有三种固定路径（`/`、`/app`、`/code`），加上校验过的查询（`agent=`、`session=`、`work=new`）和 `pane=1`，别的地址一概不放。壳里跨源的子框架导航本来就会被导航白名单拦下，交给系统浏览器。
- 登录态：同源子框架带同一组 cookie（同站的子框架照发 `SameSite=Strict`），地址里不带凭据。会话过期时分栏文档把过期交给窗口文档（`qc.expire()`），全窗口只弹一个对话框。
- 分栏文档被单独打开时，它发现自己不在框里，就换成去掉 `pane=1` 的地址。这种情况出现在壳从 `/login` 重进、把它当成回来的地址时，或者有人直接贴了这个地址。

**三种壳内核。**下表读的是 Tauri 2.12.5 与 wry 0.57 的源码；WKWebView 另有实测，见 11.7。

| 项 | WKWebView（macOS） | WebView2（Windows） | WebKitGTK（Linux） |
|---|---|---|---|
| Tauri 的注入脚本（`__TAURI__`、`__TAURI_INTERNALS__`、拖动区）与壳的 `__QMO_SHELL__` | 只注入主框架（`forMainFrameOnly`） | 每个框架都注入，但子框架发出的 IPC 能否回到壳取决于 WebView2 版本，不依赖它 | 只注入主框架 |

### 11.3 形状与数值

- 最多 4 格，一列最多上下 2 格。「在右侧打开」在焦点那一列右边插一列；「在下方打开」把焦点那一格上下分开。这一列已有 2 格、已满 4 格、或窗口放不下再一列时不开，说一句原因。
- 尺寸按比例记：列宽之和为 1，每列里的行高之和为 1。分隔线画 1 px，能抓的范围 9 px；拖动时各格的框不接收指针。双击分隔线复原等分：列之间是所有列等分，列里是这一列上下等分。分隔线能用键盘聚焦，方向键每次挪 24 px，回车等分。
- 每格最小 320 × 200 px。内容区放不下全部列（列数 × 320 超过内容区宽）时只显示焦点那一格，其余留着不丢，⌃] / ⌃[ 换着看。
- 每格的头部就是分栏文档的顶栏：原有的标题与智能体标签，⌄ 会话菜单，原有的动作（Work 的会话面板，Code 的 Remote 与变更），最后是关闭 ×。⌄ 里是这一行在侧栏 ⋯ 里的项，再加「只留这一栏」「关闭分栏」。
- 焦点格：两格以上时外框一圈 1 px 的主题色（45% 不透明），其余格子的头部文字淡一级。点进一格、或焦点移进一格，它就是焦点格。
- 在侧栏点一行：单栏时照旧；分栏时在焦点格里打开，格子里的文档自己换，不重载。侧栏把焦点格的那一行标成当前。已经开在某一格里的会话再打开时，焦点移过去，不开第二份。
- 打开分栏有三种办法：
  - 从侧栏拖一行到内容区。落在一格的右三分之一是右侧分栏，下三分之一是下方分栏，其余是在这一格里打开。拖动时画出落点。
  - 行 ⋯ 与右键菜单里的「在右侧打开」「在下方打开」。
  - ⌃⌘\ 和 ⌃⌘- 在右侧或下方开一格新的：Work 是「开始一项工作」，Code 是新会话。
- 从单栏进分栏时，原来那条会话成为第一格，没发出去的草稿跟过去。关到只剩一格时回到普通单栏：窗口文档自己打开那一格的会话，格子拆掉，草稿带回来。
- 快捷键（Windows、Linux 上 ⌘ 换成 Ctrl，⌃⌘ 换成 Ctrl+Alt）：
  - ⌘B 侧栏，原来的 ⌘⇧S 仍然可用；
  - ⌃⌘\ 右侧新开，⌃⌘- 下方新开；
  - ⌃] / ⌃[ 下一格 / 上一格；
  - ⌃⌘W 关闭焦点格。
  - 按着 AltGr 时不算，免得德语等键盘上打 `\` 时误开分栏。
- 布局记忆：`localStorage` 的 `qianmo.split.work` 与 `qianmo.split.code`，每份 `{v: 1, cols: [{w, rows: [{h, q}]}], focus}`。读写都包在 try/catch 里；版本、格数、比例、查询任一项不合规就整份丢掉，退回单栏。
  - 打开页面时，地址明确指了一个会话（`?agent=`、`?session=`、`?work=new`）而布局里没有它，就把它放进焦点格；布局里有，就把焦点移过去；地址什么都没指，原样恢复。
  - 分栏时窗口的地址跟着焦点格走（`replaceState`），后退键不在格子之间来回；格子里的移动也只换它自己的地址。
- 打不开的会话：
  - Work 的分栏文档照常画失败那一行，头部的 × 能关掉。
  - 整份文档没载进来（错误页被 `frame-ancestors 'none'` 挡住、网络断了），或 Code 的会话已不在运行器里，窗口文档在那一格画一句「这个会话打不开」和关闭按钮。

### 11.4 侧栏收起与悬停浮出

- 收起：侧栏头部的按钮与 ⌘B，状态按设备记在 `qianmo.front.side`（已有）。收起后按钮在内容区左上角，macOS 壳里从红绿灯右边起（`--shell-lights-x` 80 px，参照值是 74 加 6 px 留白）。分栏时它浮在左上那一格的头部上，那一格的头部给它让出位置。
- 悬停：收起时鼠标在按钮上停 `PEEK_OPEN_MS` = 300 ms，侧栏作为浮层从左边滑出，200 ms，`--ease-out`。浮层离窗口边 8 px，圆角 `--radius-panel` 12 px，阴影 `--shadow-lg`，盖在内容上，内容不动。
- 收回：指针离开「按钮＋浮层」后过 `PEEK_CLOSE_MS` = 250 ms 收回，120 ms；这段时间里回来就不收。浮层里开着 ⋯ 菜单或右键菜单、正在拖一行、焦点在浮层里、或浮层里开出的对话框还开着时都不收。
- 浮出时点按钮就是正式展开。Esc 收回，焦点还给按钮。
- 键盘：Tab 到按钮上就浮出（不等），焦点离开按钮与浮层后收回；回车正式展开。
- 没有悬停（`(hover: none)`）或窗口 ≤ 700 px 时，点按钮是抽屉：窄窗口用已有的抽屉，宽的触屏用同一个浮层加遮罩，点遮罩收回。
- `prefers-reduced-motion` 时不滑动，只有透明度变化。
- 浏览器的 `/`、桌面版的 `/app` 和 Code 用同一份脚本 `FRONT_SPLIT_JS`，行为一样。

### 11.5 壳

- macOS 菜单「视图」加六项：侧栏 ⌘B、在右侧新开分栏 ⌃⌘\、在下方新开分栏 ⌃⌘-、下一个分栏 ⌃]、上一个分栏 ⌃[、关闭分栏 ⌃⌘W。
- 不加壳命令。这几项和「设置… ⌘,」一样：主窗口显示的是已登录中枢的页面时，执行一段固定脚本 `window.__qmoMenu&&window.__qmoMenu('<动作>')`（动作是六个固定词之一，不拼变量）；否则什么都不做。
- 不双触发：WKWebView 先把带修饰键的按键交给页面（WebKit 的 `performKeyEquivalent`），页面 `preventDefault` 了，菜单就不再触发；页面没接，按键才回到菜单。页面接这六个键时一律 `preventDefault`；焦点在格子里时由分栏文档接住，转给窗口文档。所以按键只走页面一次，菜单只有用鼠标点时才经 `__qmoMenu` 走同一个函数。Windows、Linux 没有菜单栏，只有页面的按键。
- `qmo_boot_layout` 不变：首帧骨架只画侧栏和一格，分栏在页面起来后画。

### 11.6 放弃的方案

- **同一文档里多实例化前台脚本**：改造面是全部前台脚本，`CODE_JS` 的预算装不下（11.2）。
- **每格自己开流，再限分栏数**（比如最多 3 格）：仍会和多开的标签页、Code 的流叠在一起撞上 6 条。转发以后与格数无关。
- **`BroadcastChannel` 或 `SharedWorker` 共用一条流**：会串到同一浏览器的其他标签页和窗口；WKWebView 对 `SharedWorker` 的支持也靠不住。同源的父子框架直接调用更简单。
- **混放 Work 与 Code**：Code 的运行器通道只在 Code 文档里登记，Work 的流只在 Work 文档里有，混放就要两样都开，长连接翻倍。侧栏一次只列一种模式的会话，也没有地方把另一种拖进来。
- **纯 CSS 的 `:hover` 浮出**：做不到停顿和宽限，开菜单、拖动时会被收掉。
- **分栏头部画在窗口文档里**：Code 的 Remote 与变更面板、Work 的模型标签与会话面板都在分栏文档的顶栏里，搬出来要再做一套转发。
