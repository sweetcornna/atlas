## §0 口径

- **公开版是什么**：同一份代码的一种**部署形态**，由运营方运行，用独立的构建产物 `qm-public-<平台>-<架构>`（版本常量固化为 `public`）与独立的部署模板。自用版（默认）不受影响。
- **「仅可购买订阅使用」靠服务端闸住**：阡陌是 AGPL-3.0，任何人都可以拿源码自建并接自己的 key，这是许可证给的权利。公开版能收费的是运营方提供的服务——托管节点与经运营方网关的模型额度。所以闸门放在服务端：没有有效订阅，中枢不放行会话，magpie 不认密钥。不做客户端混淆、许可证密钥或「防破解」。
- **AGPL §13**：公开版的每个公开页面页脚都给出对应源代码的链接（配置项 `sourceUrl`，必填），NOTICE 一.6 已写明我方自己的公开部署同样适用。
- **模型只经平台网关**：公开版里订阅者的智能体（三种底层都一样）只用绑定到其租户的 magpie 档案；控制台的预设目录只剩 `magpie`；订阅者既看不到、也拿不到网关密钥（密钥只下发到他的节点）。上游只接 API key 类供应商，不转售任何个人订阅额度（章程 §5.2③、L-6）。
- **收款走官方接口**（章程 §7.2 第 8 条）：微信支付 APIv3 Native 支付、支付宝开放平台当面付（预下单生成二维码），外加运营方发放的兑换码。两种支付通道没有在真实商户号上跑过，标「未评估」。
- **法律前置**：章程 §8 写明 M3 计费落地的前置是 L-2 / L-5 的法律口径取得书面结论；v3.5 把计费的**开发**提前，这条前置对**开始收取真实款项**仍然成立（L-5 已结，L-2 待结）。
- **对外表述**：公开页面的文案过 §5.8 第 1–3 条与禁用表述；不暗示与模型厂商或 magpie 作者有授权、合作、背书关系。

## §1 用户路径

```
/plans（公开）→ 注册或登录 → 选套餐与付款方式 → 二维码页（轮询订单）
  → 支付平台回调 /v0/billing/notify/<通道>（验签、核金额、幂等）
  → 订阅延长 endsAt → 自动建租户并映射账号 → magpie 签发租户密钥（套餐额度与模型白名单）
  → 平台运维把节点分给该租户 → 中枢把租户的 magpie 档案下发到这些节点 → 前台可用
到期 → 中枢停用该密钥（magpie off-key）→ 前台显示已到期 → 续费后重新启用
```

- **预付周期，不做代扣**：套餐 = 价格 + 天数。再次购买从 `max(现在, 到期时间)` 起延长。不签微信委托代扣或支付宝周期扣款。
- **节点分配**：章程与 [`tenancy-m2.md`](./tenancy-m2.md) §2 要求一个节点只属一个租户、中枢所在主机不放用户节点。付款后自动建租户、映射账号；节点由平台运维分配（现有租户配置），分配前前台显示「节点分配中」。不在本包里申领云实例（真实云资源仍须负责人审核）。

## §2 闸门（公开版开启时）

| 位置 | 规则 |
|---|---|
| 前台 `/` | 未登录 → 公开首页（套餐、登录、注册、源代码链接）；已登录无有效订阅 → 订阅页；有订阅无节点 → 「节点分配中」；否则进入对话 |
| 会话、唤醒、作业等接口 | 成员调用前查订阅，无效回 402 `subscription_required` |
| 模型服务 | 预设只剩 `magpie`；写入其他预设回 `edition_public_magpie_only`；租户的节点只能指派绑定到该租户的 magpie 档案 |
| 网关 | 订阅到期或退款后 `off-key`，magpie 直接 401，节点侧即使缓存了配置也用不了 |
| 平台运维 | 不受订阅闸门约束（`platformSubjects`） |
| 旧 token | 公开版强制 `--legacy-view-token off`，不开 break-glass 之外的共享 token |

公开版的启动校验：必须同时有 `--accounts`、`--tenancy`、`--open-registration`、`--providers`、`--magpie` 与 `--billing <配置>`，缺一项拒绝启动；公开版构建产物里这些不能被关掉。

## §3 `@qianmo/billing`

| 部件 | 定案 |
|---|---|
| 配置 | `billing.json`（严格模式，未知字段拒绝）：币种 CNY、`sourceUrl`（必填）、`termsUrl`、套餐表（id、名称、价格分、天数、说明、网关额度 `limits[]` 与模型白名单 `models[]`）、通道配置（商户号、证书序列号、各类密钥的**文件路径**）、订单有效期。价格只出现在运营方配置里，代码与文档不写定价 |
| 秘密 | 商户私钥、APIv3 密钥、支付宝应用私钥与公钥、微信支付公钥都是 0600 文件，只按路径引用，任何报错、日志、账本行都不出现内容 |
| 账本 | bun:sqlite，`qianmoConfigPath('qianmo','console','billing.sqlite')`，0600、WAL；订单、订阅、兑换码三表，外加一张 SHA-256 哈希链事件表覆盖每一次状态变化，可校验链完整性。金额一律整数分 |
| 订单 | 每个账号 + 套餐 + 通道同时只留一张未过期的待支付订单；`out_trade_no` 32 位字母数字；到期关单 |
| 回调 | 验签 → 解密（微信 AEAD_AES_256_GCM）→ 时间戳 5 分钟内 → 商户号、应用号、订单号、金额、币种逐项相符 → 幂等记已付 → 延长订阅 → 开通网关。开通失败不丢款：记「待开通」，由定时清扫重试 |
| 兑换码 | 平台运维批量生成，明文只显示一次，落盘只存哈希；绑定套餐与周期数，可设失效时间，一次性 |
| 退款 | 在商户平台操作；控制台只登记并相应缩短订阅 |
| 清扫 | 每分钟一次：到期停用、重试待开通、关闭过期订单；幂等 |

网关开通经接口 `GatewayProvisioner { ensure(subject, plan.gateway); setEnabled(subject, on) }`，由中枢用 P33 的 `MagpiePort.bindTenant` / `setBindingEnabled` 实现。

## §4 页面

全部沿用控制台技术形态（服务端渲染、零依赖、CSP 按哈希、文案门禁），样式用现有的令牌与组件，与「注册」页同一套版式。

| 路径 | 谁能看 | 内容 |
|---|---|---|
| `/plans` | 公开 | 套餐卡片（名称、价格、周期、额度说明）、登录与注册入口、源代码链接 |
| `/subscription` | 已登录成员 | 当前套餐、到期时间、本周期网关用量（magpie 估算）、订单记录、续费、兑换码 |
| `/subscription/checkout` | 已登录成员 | 选通道下单，显示二维码（零依赖 SVG 编码器），轮询订单状态 |
| `/admin/billing`「订阅」 | 平台运维 | 订单、订阅、兑换码批量生成、手动开通与延期、登记退款、账本链校验 |
| `/v0/billing/notify/wechatpay`、`/v0/billing/notify/alipay` | 支付平台 | 公开回调，只认签名，不走控制台的 CSRF 头 |

## §5 独立构建与部署

- `bun run atlas:build:public` 产出 `dist/qm-public-<平台>-<架构>`：在生成的 `provenance.ts` 里固化 `EDITION='public'`；该产物的 `qm console` 恒为公开版，按 §2 校验启动参数。
- 部署模板 `demo/env/public/`：magpie 与公开版中枢各一个 systemd 单元、`billing.json` 示例（价格留空待运营方填）、TLS 前置示例。只是模板，不执行部署；实际开放公测仍按章程 §2.5 由负责人审核。

## §6 包表与完成标准

| 包 | 内容 | 完成标准 |
|---|---|---|
| P35.1 | `@qianmo/billing`：配置、账本、订单与订阅、兑换码、清扫 | 链校验能发现篡改；续费延长、到期停用、开通失败重试、二次回调幂等都有用例 |
| P35.2 | 微信支付 Native 与支付宝当面付通道 | 签名与验签、AES-GCM 解密、原文验签、过期时间戳、金额或应用号不符各有用例（假服务与测试内生成的密钥）；真实商户号**未评估** |
| P35.3 | 公开版闸门与页面 | §2 每条闸门有正反用例；页面过路由、文案、角色、依赖各门禁 |
| P35.4 | 独立构建与部署模板 | 公开版产物启动参数不全时拒绝启动；冒烟能起来并显示 `/plans` |

## §7 不做

- 不做按量后付费账单、发票、代扣续费、经接口退款、优惠券与分销。
- 不向订阅者暴露网关密钥，不提供「把额度用在别的工具里」。
- 不做口令登录与第三方 OAuth 登录（章程 N-2 仍不解禁）；账号沿用个人凭据。
- 不在本包里申领云实例。
