## M2 技术边界

- 租户是共享节点与数据的一组人；一个节点只能属于一个租户。中枢不运行用户可驱动的节点。协议里的证书与 capability 不加未经迁移的租户字段；租户策略从受信部署配置派生。
- 注册中心高可用使用多实例 API 加 PostgreSQL 事务存储；数据库自身的主从与自动故障转移交由部署的 PostgreSQL 集群。单机数据库实验只证明 API 横向与一致性，不声称端到端高可用 SLA。
- 开放注册默认关闭；启用后仍受注册速率、账户总量和资源分配上限约束。账户创建不自动获得跨租户节点或运维权限。
- 负责人确认当前不能自动申领新实例，本轮通过现有资源池模拟弹性扩缩容；不会创建收费实例。模拟保留容量、预算、冷却期、审批、幂等与失败恢复约束，材料明确标注模拟验证。
- A2A 在边界适配，不把第三方声明的身份、taskId、状态或 ACK 当作阡陌已经持久受理的证据。不在本轮增加支付、营销或订阅身份冒用。

本清单状态随真实实施回写；总体验收完成前不把 roadmap 的 M1/M2 出口改为已达成。

**语义记忆启用结论**：旧v1完整比较730次调用的A4失败结果保留。新v2宿主原文摘录协议在冻结独立数据上的468次正式任务（234对）均完成；A0和E1通过，E2误归因非劣效失败（ΔHRmis=0.07857，上界0.14286>0.05），A4亦失败（M0接受10条、M1接受22条伪造决策题引用）。逐字真实来源不能证明与问题相关。维持语义增强默认关闭及确定性M0回退，不能将协议加固或离线检索提升写成质量总出口通过。原机判、两份匿名语义补审与真实预算账本均保留，详见 [本轮测量](./memory-m1.md)。
