# 阡陌 v2.47.0 GitHub Release

v2.47.0 是从 `main` 切出的功能版，上一个从 `main` 切出的版本是 v2.46.3。v2.46.4 是在 v2.46.3 上单独打的补丁版，它那一项修复（MiMo 预设换成 v2.6）在 `main` 上同样存在，本版照常包含。发行形式与 v2.46.3、v2.46.4 相同：`sweetcornna/atlas`，源码归档加 `SHA256SUMS`。基座 pin 仍为 v2.46.0，不含上游同步。

## 主要变化

### 模型服务（P18）

- **控制台「模型服务」页**：像 CC Switch 那样从预设新建档案、填密钥、测连、保存并切换；节点矩阵显示每个节点期望与实际的配置、漂移、节点算出的 effort 与上下文窗口；可导入导出（导出不含密钥与指纹）。写操作要个人账号的 ops 角色，并记入动作账本。
- **中枢持钥与第六类动作**：密钥在中枢逐把加密保管，经 SSH 强制命令 `qm provider serve-stdin` 下发到节点；节点侧 `qm provider status / probe / models / apply / autocompact`。
- **resident 空闲时热切换**：下发后等常驻进程空闲才换代，在途回合不受影响。
- **多 key 轮换**：同一份档案可挂多把 key，按会话选定、按错误分类换 key 并冷却；同一会话没有遇到需要换 key 的错误时始终只用一把。
- **上下文窗口**：每个智能体默认按 200 000 token 编译，可在档案、节点矩阵、节点详情三处改。
- **自动压缩阈值**：`/autocompact` 在终端、ACP 会话、控制台对话页都可用，ACP 会话还支持 `/compact`、`/context`。
- **调用层兼容修复三批**（参照 hermes agent）：止血、推理一致性、韧性，包括 fallback 模型、Retry-After 上限、流空闲超时、工具结果图片降级等。
- **提示缓存命中**：按会话固定提示上下文快照与缓存 key，减少无谓的零命中。

预设里的「评估」状态如实显示：没有用真 key 冒烟过的预设一律标「未评估」。本版不声明对任何未评估厂商的兼容。

### 控制台

- 多路由外壳；账号与访问、操作记录；消息链列表（倒序、游标分页、搜索、增量轮询）；节点详情（概览、智能体、生命周期、模型四个页签）；智能体生命周期（发布、暂停、恢复、退役，出口检查对暂停与退役的地址拒发）；告警与值守作业页。
- 控制台动作账本：所有写操作先准入再记账。
- 商业级收口（P1）：刷新失败点亮连接状态并按失败次数退避；写操作在途时按钮置忙、可停止等待；错误一律给中文短句，原文折进「详情」；亮色和暗色两套主题的文本对比度达到 WCAG AA；375 px 宽的手机上能读状态、能发对话；时间按浏览器时区显示并标明时区。
- 安全与性能：地址栏里的令牌换成会话 cookie（`HttpOnly`、`SameSite=Strict`）；脚本按 sha256 哈希放行，补上 COOP、CORP、Permissions-Policy，TLS 下发 HSTS；GET 响应按需 gzip 压缩。
- 修复：取消确认框后在几毫秒内重开同一个确认框时，确认可能不生效、什么都不发。人手点不到这么快，自动化脚本会碰到。

### 本地—云端接力（P17，本仓库部分）

- `qm handoff` 本地命令、中枢 `/v0/handoff` 与接力台账；模型回合内可用的 `qm handoff mcp`。
- 节点桥 `qm handoff node` 与中枢派发：把转交的任务交给节点上的 app-server 续跑，结果取回中枢。
- `qm handoff attach`：经 SSH 隧道从本机接入云端正在运行的会话，节点令牌不经中枢。`qm handoff pull`：把云端结果接回本机，本地没动过时快进，动过时另开 `qianmo/<任务>-return` 分支、工作区文件不动。
- 接力的真机续跑、远程接入与关机演练（P17.7）尚未做，本版只包含本仓库这一侧和离线、单机验证。

### 其他

- 授权对象与 GrantStore（P14.2/P14.3）；注册中心写 token 与见证信任加固（P15.8）；CA 多根信任、签发台账与到期分档（K-1）。
- 邀请令牌与个人账号最小形态（P15.3/P15.5）、语义召回层（P16.6）：**默认关闭**。
- ACP 会话退出前刷写会话记录；带符号链接的 cwd 续会话不再为空。
- 内测舰队运维：模型服务迁移的专用 key 登记助手、每轮真机验收脚本（AC-P6），以及 `beta-env.md` §13 的迁移与验收手册。

## 升级注意

- 模型服务的写操作要求控制台开启 `--accounts` 与 `--providers`，并用 ops 角色的个人账号登录。
- 节点首次接受下发后，`settings.json` 成为模型配置的唯一来源。ACP 子进程会剥掉 provider 类环境变量，`model-env` 里残留的这类键不再生效；控制台会提示 `env-residue`，下一个维护窗口删掉即可。
- 多 key 档案的非主 key 存在节点的 `qianmo/key-pool.json`（0600），与 `settings.json` 同等保护。
- 上下文窗口默认 200 000 token；此前依赖模型默认窗口的部署，行为会因此改变，可在模型服务页改回。
- 不开 `--accounts` 的控制台，带 `?token=` 的地址会 303 跳转到去掉令牌的同一地址，并改用会话 cookie。已有的书签照常可用，地址栏和历史记录里不再留令牌。
