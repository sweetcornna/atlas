## 0. 问题定义

出口判据原文：「检索命中率与幻觉引用率有量化指标并优于 M0 基线」。起草时的事实：

1. **M0 只有通过/不通过，没有比率。** AC-4 的证据是 5 条决策 × 2 家命中 10/10、3 条伪造决策 × 2 家引用数 0/6（roadmap P3.3 完成记录；负例判定点是「被接受的引用为空」，`tests/integration/qianmo-memory-recall.test.ts:578`）。它只覆盖全量注入模式下的 5 条条目。
2. **M0 从未在注入阈值之上测量过。** 阈值为 50 条 / 20 000 字符（`packages/recall/src/inject.ts:56-59`）。阈值以下候选全部注入，D-6 的「词表不匹配 → 0 结果」失败面被结构性消除；阈值以上靠排序截断，该失败面会回来。
3. **常驻链路没有引用强制点。** P13.7（`d9bd024b`）只把记忆块注入用户消息（`packages/resident/src/memory-sidecar.ts:197`，仅调用 `renderInjection`）。在 `src packages tests scripts` 下 grep `handleMemoryAnswer|verifyCitations|MEMORY_ANSWER_TOOL`，除 `packages/recall/` 自身外只命中 `packages/resident/test/memory-sidecar.test.ts` 与 `tests/integration/qianmo-memory-recall.test.ts` 两个测试文件，没有生产调用方。`resident-botization.md` §4.4 所写「AC-4 判据由既有 `verifyCitations` 承担」在库层有测试（`memory-sidecar.test.ts:261`、`:275`），在运行路径上没有接线。

本稿做三件事：把两个指标定义到可计算；给出检索层的可复现 M0 基线（已执行，§3）和回答层的测量协议（未执行，§4）；在同一套测量方法上设计语义叠加（§5）与治理（§6），让「优于基线」可以机判。

## 2. 指标定义

### 2.1 检索层（离线、确定性，不需要模型）

记号：查询 q；gold 集 G(q) 为应当到达模型的条目；禁入集 F(q) 为不得到达模型的条目（已 revoke、事件轴已失效、在其他 scope）；候选集 C(q) 为 scope 内全部 live 条目；R(q) 为 C 的全序排序；注入集 I(q) 为套预算后 R 的前缀。

| 指标 | 公式 | 何时有信息量 |
| --- | --- | --- |
| recall@k | \|G ∩ R[1..k]\| / \|G\| | 衡量排序本身；G 为空的查询不计入均值（既不算 0 也不算 1） |
| MRR | 均值 1 / rank(R 中第一个 gold) | 同上 |
| 候选集召回 | \|G ∩ C\| / \|G\| | 由 I-1 保证恒为 1，作不变式监测，不是质量指标 |
| **注入覆盖率** | \|G ∩ I\| / \|G\| | **核心指标。只在 \|C\| 超过阈值（`mode="ranked"`）时有信息量**；全量模式下由构造恒为 1 |
| 禁入泄漏 | Σ\|F ∩ I\| / Σ\|F\|（另报 Σ\|F ∩ C\|） | 安全不变式，目标恒为 0 |
| top-1 诱饵 | 排第一的条目不在 G 且词面相关度 > 0 的查询数 | 描述回答层要面对的词面诱饵压力，不作优劣判定 |
| full 模式占比 | `mode="full"` 的查询数 | 决定「块里没有 = 库里没有」是否成立（`inject.ts:159-171` 把这一点写进块头） |

### 2.2 回答层（需要真实模型）

每题一次 `qianmo_memory_answer` 调用，经 `handleMemoryAnswer` 得到每条引用的六种判定之一。P 为正例集合，Q 为全部查询，S(q) = G(q) ∪ 标注为可接受的相关条目。

- **命中率** H = \|{q ∈ P：首轮 accepted，G(q) ∩ accepted ≠ ∅，且 `mustMention` 全部出现}\| / \|P\|。
- **幻觉引用率**拆成两个，分开报告：
  - **伪造引用率（拦截前）** HR_fab = 判定为 `unknown` 或 `malformed` 的引用数 / 全部引用数；另报按题口径（含至少一条伪造引用的题占比）。它衡量模型倾向。工具层会拦下这类引用，不会到用户面前。
  - **误归因率（拦截后，用户可见）** HR_mis = \|{q：accepted 中存在 c ∉ S(q)}\| / \|Q\|。伪造决策负例 S = ∅，任何被接受的引用都算，与 AC-4 集成腿的判定一致（`:578`）。这是工具层**拦不住**的一类：真实、已注入、live 的 id，被拿来支撑它不支撑的结论。
- **单独报告、不计入幻觉**：`unreadable`（真条目损坏，记为存储故障率）；`retired` 与 `not-injected`（真 id 但不在本轮证据内，记为越界引用率）。

**与任务书口径的差异**：任务书把 `unreadable` 列入幻觉引用。本稿不采纳，因为 `citation.ts` 头注释与 recall README 不变式 2 已经把「损坏的真条目报成伪造」定为本链路最坏的错误，把它计入幻觉率会让指标奖励这种合并。列为决策点 D-2。

### 2.3 数据集与规模档位

实现见 `packages/recall/eval/dataset.ts`。条目 key 是标签，存储 id 由评测按计数器分配。

| 类型 | 数量 | 标签 | 用途 |
| --- | ---: | --- | --- |
| 正例·词面重叠 | 20 | G = 1 条 live 决策 | 问题与条目共享排序 token（实测 gold 相关度 ≥ 2） |
| 正例·零词面重叠 | 20 | G 同上 | D-6 形态：在现有排序器下 gold 相关度 = 0，由测试用真实 `scoreEntry` 逐题校验 |
| 负例·伪造决策 | 8 | G = F = ∅ | 从未写入；其中 2 题与填充条目高度同词（诱饵） |
| 负例·已废止 | 4 | F = 被废止条目 | 2 条 `revoke`、2 条写入时带 `invalidAt`；其中 2 题 G = 取代它的 live 条目 |
| 负例·跨 scope | 3 | F = 他处条目 | 其他 project、同 project 的 working 层、baseline 层各 1 |
| 跨 scope 孪生 | 5 | 挂在对应正例的 F 上 | 其他 project 中与 gold 近乎同文、结论相反的条目 |
| 填充 | 按档位 | 无 | 24 主题 × 12 设置 × 8 取值中按种子无放回抽样（上限 2304） |

档位按目标 scope 内 live 条目数计：**30**（低于阈值，实测 55/55 题为 full 模式）、**500**、**2000**。种子 `20260926`；`asOf = 2026-09-01T00:00:00Z`；入库时间在 1–365 天前按种子均匀抽样。

局限：语料是合成的，以中文为主，每题只有 1 条 gold，问题不带标签（与常驻 sidecar、AC-4 腿的调用形状一致）。数字只描述这份语料，不代表真实节点记忆。

## 5. 语义检索叠加方案

### 5.1 融合：保底配额 + RRF

- **全量模式不启用语义层**（I-2）。只有 `mode="ranked"` 时才融合。
- 设 I_det 为 M0 的注入集。先原样保留 I_det 的前 ⌈\|I_det\|/2⌉ 条（确定性保底），再按 RRF（k = 60）融合确定性名次与语义名次，从 C 的其余条目中依次填充，条数与字符预算规则沿用 `selectForInjection`。
- 「叠加非替换」的可机检定义：**保底部分 ⊆ I_hybrid**，且 **I_hybrid ⊆ C**。
- 放弃纯 RRF：它不保证确定性前列留存，D-6 修好的东西可能被语义排序挤掉。放弃分数加权：两套分数量纲不同，权重没有可解释的定标方法。放弃语义过滤候选：违反 I-1。
- 块头在 ranked 模式下增加检索方式属性（如 `retrieval="hybrid"`），full 模式块头不变。

### 5.2 embedding 来源：模型中立

- 接口 `EmbeddingProvider { id, model, dimensions, embed(texts) }`，`@qianmo/recall` 内不出现供应商名（I-5）。
- 三种配置：`off`（默认）、本地（进程内或本机服务）、OpenAI 兼容 embeddings 端点（经 provider 档案配置）。切换只改配置，与 AC-5「仅改配置不改代码」同一口径。
- 不同 provider / model / 维度的向量不混用：索引键为 `(entryId, contentHash, providerId, model, dimensions)`，键不匹配即视为缺失。
- 远端 embedding 会把记忆正文发出节点，默认关闭，开启须负责人批准（D-3）。

### 5.3 索引

- 放在 `<memoryRoot>/index/`，不在 `working/`、`project/`、`baseline/` 之下。store 只扫描这三层（`packages/memory/src/store.ts:158` `searchRoots`、`:440` `#locate`），条目文件格式不变，基座可读性不受影响。
- 索引只存 id → 向量，条目内容永远从 store 读。索引中的 id 解析不到或不在本轮 C 中即丢弃，所以被污染的索引最多影响排序，不能注入条目（T-7 / ASI06）。

### 5.4 失败回退与接线约束

- embedding 报错或超时（提议 300 ms，可配置）时，本次召回退回确定性结果，结果上标 `retrieval: 'deterministic' | 'hybrid' | 'hybrid-degraded'` 并记一条事件（I-6、I-7）。
- `recall()` 保持同步、行为不变；另增异步的 `recallHybrid()`。常驻组装是同步路径（`src/services/qianmo/residentPrompt.ts:58`，`renderMemory` 返回 string），查询向量须在组装前就绪，超时即走同步 `recall()`。具体接线由 P16.6 确定。

### 5.5 成本上限

每次召回最多 1 次查询向量 + 32 条缺失条目补算；每节点每日调用上限为配置项，默认 0（即关闭）。评测报告记录 embedding 调用次数。

### 5.6 与工具层强制引用的关系

强制点不变：`handleMemoryAnswer` 以 `injectedIds(result)` 为白名单逐 id `getEntry`（`citation.ts:230`）。语义层只改变哪些 live、in-scope 条目进入 I，不引入任何新的可引用来源。它的副作用是注入集里「词面不同、语义相近」的条目变多，误归因（HR_mis）的机会随之上升。所以出口判据要求 HR_mis 不劣于基线，与命中率同时判定（D-1）。

## 6. 治理

### 6.1 冲突消解

- 定义：同一 scope 内两条 live 条目对同一决策给出不同结论。
- 提议：新增 `qm_supersedes` 字段（`qm_*` 命名空间，memory README 不变式 5）。写入新条目时声明取代的 id，store 对旧条目执行 `invalidate(at = 新条目 validAt)`。走事件轴而不是 `revoke`，因为旧决策在它有效的时段里是真的，问过去仍应答得出。
- 自动检测只出报告：同标签、语义相近、结论不同的条目对进入待审清单，不自动 invalidate 或 revoke。自动裁决判错一次，就是把一条真记忆撤下，与 I-3 防的是同一类错误。

### 6.2 过期与废止：与现有双操作的对应

| 场景 | 操作 | 轴 | 现状 |
| --- | --- | --- | --- |
| 已知到期的事实 | 写入时带 `invalidAt` | 事件轴 | 已有：`entry.ts:142`、`:291` |
| 事实自某时刻起不成立 | `invalidate(id, at)` | 事件轴 | 已有：`store.ts:402` |
| 记录本身错误或不该存 | `revoke(id, {reason, by})` | 摄取轴 | 已有：`store.ts:369` |
| 被新决策取代 | `qm_supersedes` → `invalidate` | 事件轴 | 新增（P16.9） |
| 长期未复核 | 只出复核报表，不做任何写操作 | — | 新增（P16.10） |

不新增第三种退役类型；任何自动策略都不调用 `revoke`。

### 6.3 跨项目 / 跨 scope 隔离

现状：分区是目录级的（`store.ts:158`），召回按 scope 传参；常驻链路只取 working 层，`(agent, contextId)` 经带 `v-` / `d-` 标签的单射映射成目录段（`memory-sidecar.ts:84-114`）。§3 基线的禁入泄漏为 0。

缺口：

1. `getEntry` 经 `#locate` 扫描全部三层（`store.ts:440-454`）。引用其他 scope 的真实 id 得到 `not-injected`，伪造 id 得到 `unknown`，回给模型的 rejection 文本也不同（`citation.ts:215-222`），对模型构成跨 scope 的存在性探针。id 含 64 位随机数（`store.ts:89-91`），猜中不现实，当前风险低；多租户下应收紧为：不在本轮 scope 的 id，回给模型的文本与 `unknown` 相同，内部报告仍保留六分。
2. project / baseline 层在常驻链路上不可达，上下文之间共享知识只能经 `archiveWorkingMemory` 显式沉淀，而沉淀目标 `projectKey` 如何由 `(agent, context)` 决定尚无规定。

与 `tenancy-m1.md` 的接口点（本稿只列接口，不做决定）：

1. 租户维度进入存储的位置：每租户独立 `memoryRoot`，或 scope 键前缀。本稿只要求它是目录级分区，而非查询过滤。
2. `getEntry` 的查找范围限定在租户根之内。
3. 评测数据集增加「跨租户孪生」负例，禁入泄漏按同一口径计量。
4. embedding 索引与 §5.5 的调用上限按租户计量。
5. 远端 embedding 开关的授权主体（租户管理员还是节点 owner）。

## 8. 明确不做

- 替换确定性检索，或用语义分数过滤候选（I-1）。
- 外部向量数据库服务；索引只用文件。
- 生成式模型进入召回路径（重排、查询改写）；这是基座 `findRelevantMemories` 的路线，recall README §4 已记录不采用的理由。
- 由模型自动抽取并写入记忆。
- 自动 `revoke`、自动冲突裁决。
- 供应商原生引用块（D-6）。
- 跨节点记忆同步。
- 在测试里把基线数字写成断言。

## 10. 存疑与未验证

- 回答层全部未测量；§4 的 990 次调用规模与 token 成本是估算。
- 合成语料的代表性未验证；只有中文为主、单 gold、问题不带标签这一种形态。
- 基线只在 macOS 上跑过。计算不依赖 locale 与目录读取顺序（排序是全序），但 Linux 未实测。
- 字符预算按 `renderEntry` 长度计，未换算成 token。
- 300 ms 超时、⌈\|I_det\|/2⌉ 保底、RRF k = 60、每次 32 条补算都是提议值，未测量。
- 事实 3（常驻链路无强制点）基于 grep；若存在未走 `@qianmo/recall` 导出名的间接调用，本稿会漏检。
