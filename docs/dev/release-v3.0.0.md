# 阡陌 v3.0.0 GitHub Release

v3.0.0 是换基座之后的第一个正式版本，收录 v2.47.2 以来的全部改动。产品代码与 v3.0.0-beta.1（`2f99b057`，10 月 12 日部署到内测环境的那份产物）相同，标签所在提交只多了发行说明和 NOTICE 里一处快照提交号的更正，可以用 `git diff --stat 2f99b057 v3.0.0` 核对。`qm --version` 仍自报 `3.0.0-dev`，识别产物以编译进去的源码提交为准（CONTRIBUTING §11）。发行形式与 v2.47.x 相同：`sweetcornna/atlas`，源码归档加 `SHA256SUMS`。

10 月 11 日开发的新能力仍未在服务器上逐项验证，各项状态写在「部署与验证」里；已知问题单列在后面。

## 变化

- **基座换成 qianmopi**（#199、#200、#201）：在 oh-my-pi（MIT）上改造，对应的上游快照是 v18.8.8，边界由 `base-snapshot/omp-v18.8.8` 标签守着。sync-omp 每天在隔离环境生成上游候选，合入仍走评审。
- **10 月 11 日的新方向**（#203）：
  - 接力插件：Claude Code、Codex 等支持插件的工具装上后，用配对码换设备令牌；代码和结果放在用户自己的 GitHub 仓库。
  - 节点间文件互通：用户批准后一次性传送，经用户私有的 GitHub 交换仓库。
  - 云端电脑：给节点主智能体开专属浏览器，Linux 节点还可以开专属电脑；两档确认，回收时进程和目录一起删除。
  - 按任务匹配模型、长期记忆、主动执行（定时任务）、应用连接（邮箱与日历，发信和建日程逐次批准）。
  - 中枢只做认证、授权和记账，不存代码和文件。
- **常驻节点按需启动模型子进程**（#204、#205、#206）：常驻扩展不再把基座整个打包进去；启动失败会计数，启动中也能停下；子进程有任务才开，空闲到时回收（`--omp-idle-ms`），同时存活的个数有上限（`--omp-max-children`）。
- **控制台拆成对话前台和管理后台**（#207）：`/` 是与默认智能体的对话页（由 `--chat-default` 指定），左侧按服务器列出其他节点的智能体；原来的各页移到 `/admin` 下，旧地址 308 跳转；只读账号打开 `/` 会转到 `/admin`。
- 其余：#196 修正控制台模型服务生效值的显示，#197 把 custom-openai 预设记为已评估，#198、#202、#208 是文档回写。
- 相对 v3.0.0-beta.1：NOTICE 里 `base-snapshot/omp-v18.8.8` 指向的提交号原先误抄成 v18.8.4 快照的 `8eda2911`，更正为 `b832507a`（树 `1b30d3c8` 未变）。

## 部署与验证

- 10 月 12 日部署到内测环境：中枢和两个节点运行本版的产品代码，另一个节点仍是 v2.47.2。同一份部署连续两轮验收通过，覆盖名册、握手与可达探针、模型服务生效值、签名唤醒（首段内容与完成）和对话前台。当天稍晚把原先停在中枢服务器上的一个节点迁到节点服务器，与已有节点同机运行，迁移后又连续两轮验收通过。
- 迁移后的 24 小时观察从 10 月 12 日 10:16（UTC）开始。截至 10 月 13 日 01:38，三个节点的可达、握手与唤醒探针没有失败，期间 129 个任务全部完成；窗口在 10 月 13 日 10:16 收口。
- 实测过的：对话前台的入口与跳转；节点空闲时没有模型子进程，唤醒时按需启动，空闲后回收。
- 没有在服务器上逐项验证的：10 月 11 日的七项新能力。接力插件尚未发布；文件互通要用的交换仓库、应用连接要用的邮箱与日历凭据，都没有在内测环境配置。生图、语音、视频、邮件、日历没有对真实服务评估。

## 已知问题

- 云端电脑的浏览器工具：智能体调用浏览器工具时，节点侧的参数检查要求字段与工具定义完全一致，不接受基座给工具调用附带的意图字段，所以调用都会被拒。开启、设置和回收不受影响。后续版本修复。
- 本机压力测试里，两个节点每个收件箱同时收到 25 个任务（50 并发）时，邮箱写入的锁争用使 150 个任务中 73 个被拒；20 并发及以下 108 个任务全部完成。
- 本机 60 分钟连续任务中，两个节点后五分钟的 RSS 中位比前五分钟分别高 36 MiB 和 43 MiB，目前不能区分缓存、转录增长与内存泄漏。

## 升级注意

- 从 v2.47.x 升上来是换基座：旧运行时里的会话不会迁移成新基座的上下文；模型服务配置第一次下发要带 force。
- 内存紧的节点机建议在尾参里加 `--omp-max-children=1 --omp-idle-ms=60000`，代价是唤醒冷启动多两秒左右。
- 中枢控制台加 `--chat-default <qianmo://节点/智能体>` 指定首页的对话对象；不加时取名册里第一个能对话的智能体。
- 已经装了 v3.0.0-beta.1 的不用重装，产品代码相同。
