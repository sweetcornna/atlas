## 0. 排期基础假设

在读任何日期之前，先认下面这几条，否则排期看起来会过于乐观：

1. **有效产能按 60% 估**。5 名在校生，课程、实验、竞赛都在同一时间轴上。任务包工时按"这周只有 3 个有效工作日"来估。
2. **低产能窗口显式减载**，不假装它不存在：

   | 窗口 | 迭代 | 原因 | 处理 |
   |---|---|---|---|
   | 2026-09-10 ~ 09-13 | S1 尾 | CUMCM 数模国赛（团队自己参赛） | 李怡康本期不排开发任务，改为**赛中采集真实场景素材** |
   | 2026-10-01 ~ 10-07 | S3 | 国庆假期 | S3 按 50% 产能排 |
   | 2026-12-21 ~ 2027-01-03 | S9 | 期末考试周 | S9 按 50% 产能排，只做收尾，不排新功能 |

3. **关键路径任务不排进低产能窗口**。关键路径为：
   `P0.1 → P1.1 → P3.1 → P4.1 → P6.1`（工程地基 → 会话持久化 → 休眠唤醒 → 跨节点投递 → 场景端到端）。这条链上任一环节延期，M0 整体延期。
4. **欠账阈值**：任一迭代欠账 > 30% 时，下一迭代不加载新任务包；连续两期欠账 > 30% 触发范围裁剪评审（削减 §3 范围，而非削减验收标准）。
5. **迭代节奏**：双周迭代，周一开始、周日结束。每周一次 30 min 同步会（只对齐阻塞项），每迭代末复盘 + 下期任务包确认。
6. **任务包状态**：`未开始 / 进行中 / 阻塞 / 已完成`，在每期复盘时更新本文。

### 任务包字段说明

每个任务包含：**编号 / 名称 / 负责方向（owner，backup）/ 依赖 / 交付物 / 完成判据（DoD）**。
标 ⭐ 者为关键路径，标 ⚖️ 者为法律合规关键项。

### S4 · 2026-10-12 ~ 10-25 — 跨节点投递打通（M0 最关键的一期）

**P4.1 ⭐ 跨节点任务消息端到端**

- 依赖：P2.1、P2.2、P3.1
- 交付物：完整链路——节点 A 智能体发起 → 注册中心按名解析 → 传输通道加密投递 → 节点 B 休眠智能体被唤醒 → 返回 ack → 执行任务 → 返回 result
- DoD：连续 10 次测量，ack P95 ≤ 60 s、result ≤ 5 min、成功率 10/10；链路可一键复现；**本任务包为 M0 单点风险最高项**，S4 第一周结束时若未打通端到端最小链路（哪怕只有 ack），立即启动每日站会跟踪 → **AC-2**

**P4.2 防循环与限流**
- owner：陈曦宇（backup：陈子轩）
- 依赖：P1.4、P4.1
- 交付物：
  - **防循环**：hop 上限取 `LIMITS.maxHops = 8` 作为兜底；回环在**首次回访节点即被拒收**（协议层 hops 查重已实现），远早于兜底上限触发
  - 消息指纹去重表（带 TTL，默认对齐 `LIMITS.defaultTtlMs = 30s`）
  - **限流**：运行时层的令牌桶——**单发送方对单目标** 60 s / 20 条。注意这与协议层 `LIMITS.ratePerMinute = 600`（接收节点对单发送方的**每节点入站预算**）是**两层不同机制**，两者独立生效，文档与代码中不得混写或互相覆盖
  - `loop_detected` 与 `rate_limited` 审计事件
- DoD：构造 A→B→A 回环，在**首次回访节点时即被切断（≤ 2 跳）**并产生含完整 trace_id 的审计事件；运行时节流的第 21 条消息被拒并返回明确错误码；另有用例断言协议层 600/分钟入站预算独立生效 → **AC-3**

**P4.3 权限分级与授权模型 v0**
- owner：陈曦宇（backup：喻永昌）

## M1：校内内测（2027H1，粗粒度）

**目标**：把 M0 的原型变成 20 ~ 50 名软院同学能真实用起来的内测系统；同时完成基座退场。

| 方向 | 内容 | 出口判据 |
|---|---|---|
| **基座退场** ⚖️ | 执行章程 §5.7：优先迁移到官方 Claude Agent SDK，SDK 覆盖不到的部分走净室实现；`scripts/fetch-base.sh` 从仓库删除 | **M1 硬门槛**，未完成不得进入 M2；软著申请以此为前提 |
| **注册发现产品化** | 最小 Web 控制台（智能体列表、状态、消息链查看）、账号体系、智能体生命周期管理 | 内测用户无需接触 CLI 即可完成注册与查看 |
| **权限模型上线** | 用户授权流（授权申请 → 用户确认 → 时效凭据 → 主动撤销）；权限审计报表 | 所有需确认动作 100% 经过用户授权链路，抽查无绕过 |
| **记忆能力上线** | 语义检索（在确定性检索之上叠加，非替换）、记忆治理（冲突消解、过期废止、跨项目隔离） | 检索命中率与幻觉引用率有量化指标并优于 M0 基线 |
| **生产级加密** | mTLS 替换预共享密钥；证书签发与轮换；密钥管理 | 解除章程 N-3；渗透自查无高危项 |
| **多租户与配额雏形** | 内测必需的租户隔离与用量配额（仍不做计费，N-1 保留） | 跨租户数据访问用例全部被拒 |
| **第二产品线验证** | 运维值守场景原型（常驻智能体的第二类应用） | 至少 1 个真实值守场景连续运行 7 天 |
| **稳定性目标** | 可用性 ≥ 99%（按内测时段计）、唤醒 P95 < 30 s（M0 为 60 s） | 以 P7.3 基线报告为对比基准 |
| **知识产权** | 软著申请提交；首批自研包开源方案确定并执行 | 材料齐备且经学校科技处确认 |
| **边界用例库** | 从 12 条扩到 ≥ 40 条，覆盖内测暴露的真实边界 | CI 常绿，内测期新增缺陷 80% 有对应用例 |

**M1 主要风险**：真实用户带来的边界问题数量级高于自测；基座退场的工作量在 M0 阶段难以准确估计——因此 M1 的前两个迭代预留为"退场 + 内测环境搭建"，不排新功能。
