# Qmo 桌面版的壳（P37.8、P37.11）

设计见 [`docs/dev/qmo-app.md`](../../../docs/dev/qmo-app.md)。这里只写怎么构建、壳与 `qmo`、壳与中枢页面之间的约定，以及几处不读代码看不出来的取舍。

## 目录

| 路径 | 内容 |
|---|---|
| `src-tauri/` | Rust 壳，自成 Cargo 工作区（`[workspace]` 为空），不并入仓库根的工作区；`Cargo.lock` 入库 |
| `src-tauri/capabilities/local.json` | 本地页面的能力：十一个 `local_*` 命令与两个拖动权限，只对随壳打包的页面生效 |
| `src-tauri/icons/` | 应用图标与菜单栏模板图标（见末节） |
| `ui/` | 本地页面：登录、骨架、离线、设置、关于。纯 HTML/CSS/JS，中英日三语按系统语言 |

构建产物不入库：`src-tauri/binaries/`（`qmo` sidecar）、`src-tauri/gen/`、`src-tauri/permissions/autogenerated/`（`tauri-build` 每次重写）与 `target/`。

## 构建

```sh
bun run atlas:build:app            # 发布版；macOS 上产出 target/release/bundle/macos/Qmo.app
bun atlas/scripts/build-app.ts --debug    # 调试版（开发者工具开着）
bun run atlas:dev:app              # cargo tauri dev
cd atlas/apps/qmo/src-tauri && cargo test
```

`build-app.ts` 先照 `atlas:build:client` 编出本机的 `qmo`，复制到 `src-tauri/binaries/qmo-<目标三元组>`，再 `cargo tauri build`。需要 Rust 与 `cargo install tauri-cli`；Linux 另要 WebKitGTK 开发包。各系统在本系统上构建，没有交叉构建。

## 打包与签名

`bun run atlas:build:app` 只出 `Qmo.app`。macOS 的 `.dmg` 在本机用 `ditto` 和 `hdiutil` 做（`ditto` 保住签名与资源封印，别用 `cp -R`）：

```sh
APP=atlas/apps/qmo/src-tauri/target/release/bundle/macos/Qmo.app
STAGE=$(mktemp -d)
ditto "$APP" "$STAGE/Qmo.app"
ln -s /Applications "$STAGE/Applications"
hdiutil create -volname Qmo -srcfolder "$STAGE" -fs HFS+ -format UDZO -ov Qmo-0.1.0-macos-arm64.dmg
```

- `tauri.conf.json` 里 `signingIdentity` 是 `-`：整包 ad-hoc 签名，`codesign --verify --deep --strict Qmo.app` 应通过。`hardenedRuntime` 关着：没有公证它没有用处，随包的 `qmo` 是 Bun 编译产物，开着它要另给 JIT 等授权。有 Developer ID 与公证时，用 `APPLE_SIGNING_IDENTITY` 与 `APPLE_*` 环境变量覆盖，并重新决定授权项。
- `Qmo.app/Contents/Resources/` 里随包 `LICENSE` 与 `THIRD-PARTY-NOTICES.txt`。后者由 cargo-about 生成，改了 `Cargo.lock` 要重新生成（`cargo install cargo-about --locked --features cli`）：

```sh
cd atlas/apps/qmo/src-tauri
cargo about generate --locked --config about.toml about.hbs -o THIRD-PARTY-NOTICES.txt
```

- 安装包只在 Apple 芯片的 macOS 上做，里面是 arm64。发给别人的包要在标签所在的干净提交上构建，随包 `qmo` 的 `--version` 末尾不带 `-dirty`。

## 对着预览中枢跑

没有真中枢也能在壳里看 `/app`。`atlas/packages/console/test/appPreview.ts` 在本机起一个开了个人账号的控制台：一个运维账号，五个会回话的预览智能体，设备配对在内存里（配对码、客户端配对、票据、吊销），不写盘。

```sh
bun atlas/packages/console/test/appPreview.ts           # http://127.0.0.1:38691；端口可作第一个参数
curl -s -X POST http://127.0.0.1:38691/__preview/pairing # 再要一个配对码
```

启动时打印中枢地址和一个配对码（10 分钟，用一次）。打开 Qmo，在登录页填 `http://127.0.0.1:38691` 和配对码即可。浏览器里看同一个账号：`http://127.0.0.1:38691/__preview/login?next=/app`。

不想动本机的客户端状态时，给 `qmo` 一个临时目录；壳从终端启动时，它带的 `qmo` 继承同一个环境变量：

```sh
export QMO_CLIENT_DIR=/绝对路径/临时目录
echo <配对码> | bun atlas/packages/client/src/cli.ts sign-in http://127.0.0.1:38691
bun atlas/packages/client/src/cli.ts session --json      # 打印 cookie，可拿去 curl /app
atlas/apps/qmo/src-tauri/target/release/bundle/macos/Qmo.app/Contents/MacOS/qmo-app
```

预览重启后设备全忘，`qmo` 会报 `invalid`，壳回到登录页，用新的配对码再登一次。

## 壳与 `qmo`

壳从不读设备令牌，只经管道跑随包的 `qmo`，读它标准输出上的一行 JSON：

| 命令 | 成功时输出 |
|---|---|
| `qmo session --json` | `{hub, deviceId, name, cookies: [{name, value, domain, path, secure, httpOnly, sameSite, maxAge, expires}]}`，票据已核对用掉 |
| `qmo sign-in <中枢> --force --json` | `{hub, deviceId, name}`；配对码从标准输入读一行 |
| `qmo sign-out --json` | `{result}` |
| `qmo status --json` | `{dir, signedIn, hub?, deviceId?, name?, pairedAt?, token?, device?}` |
| `qmo agents --json [--rescan]` | `{agents: [...]}`，字段见 `qmo-local.md` §4.2；页面经 `qmo_local_agents` 要，壳原样转过去 |

出错时输出 `{"error":{"kind","message"}, hub?, deviceId?, name?}`，退出码按 `kind`：

| kind | 码 | 壳怎么办 |
|---|---|---|
| `refused` | 1 | 离线页 |
| `usage`、`signed_in` | 2 | 离线页（不该出现） |
| `signed_out` | 3 | 登录页 |
| `revoked`、`invalid`、`device_kind` | 4 | 登录页，附一行说明 |
| `owner_inactive` | 5 | 离线页，可退出登录 |
| `unsupported` | 6 | 中枢没开个人账号：主窗口打开中枢自己的 `/login` |
| `network` | 7 | 离线页，5、10、20、30 秒自动重试 |
| `bad_code` | 8 | 登录页「配对码不对」 |
| `throttled` | 9 | 稍后再试 |

`qmo` 给的 cookie，壳只按中枢主机名写成 host-only，名字、值、路径不合规或 `Domain` 不是这个中枢的，整次进门作废。另加一枚 `qianmo_shell=<macos|windows|linux>`（非 HttpOnly、Lax、400 天）。

## 壳与中枢页面

中枢源（登录时的地址）在运行时得到一条 remote 能力，只含下面二十二个命令和两个拖动权限；本地命令、文件系统、shell、HTTP、对话框等插件都不给网页。参数按原始请求体逐项校验，多一个键、类型不对、超长、越界都拒绝；`qmo_local_agents`、`qmo_boot_layout`、`qmo_open_local_settings` 与十三条本机会话命令另在命令里核一次调用方页面与中枢同源，本机会话命令还只收主窗口。

| 命令 | 参数 |
|---|---|
| `qmo_shell_info` | 无；返回 `{platform, version, quickShortcut}` |
| `qmo_notify` | `title` 1–120 字，`body?` ≤ 300 字，`session?`；主窗口在前台时不发 |
| `qmo_badge` | `count` 0–999 |
| `qmo_open_session` | `session`（`[A-Za-z0-9_-]{1,128}`）；主窗口打开 `/app?session=<id>` |
| `qmo_quick_hide` | 无 |
| `qmo_sign_out` | 无；返回 `{revoked, result}` |
| `qmo_local_agents` | `rescan?`（布尔）；返回 `{agents}`。30 秒超时，同一时刻只跑一个 `qmo agents`，后到的等同一个结果；失败时以一行说明拒绝 |
| `qmo_boot_layout` | `layout`：`page`（`chat`、`agents`、`code`）、`side`、`sideWidth` 0–1000、`rows` 0–60、`labels` 0–20、`theme?`、`colors?`（`{dark, page, sidebar}`，`#rrggbb`）；存进设置，骨架页按它画 |
| `qmo_open_local_settings` | 无；打开壳的设置窗 |
| `qmo_local_list`、`qmo_local_watch`、`qmo_local_pick_folder`、`qmo_local_forget_folder`、`qmo_local_start`、`qmo_local_send`、`qmo_local_stop`、`qmo_local_answer`、`qmo_local_set_mode`、`qmo_local_read`、`qmo_local_changes`、`qmo_local_diff`、`qmo_local_set_remote` | 本机会话，见下节与 `qmo-app.md` §5.2 |

页面这一侧要做的：

- 用 `window.__QMO_SHELL__`（`{platform, window: 'main' | 'quick', version}`，冻结、不可改）判断是否在壳里，命令走 `window.__TAURI__.core.invoke`。
- 服务端看 `qianmo_shell` 渲染 `<html data-shell>`；顶栏与侧栏顶部写 `data-tauri-drag-region`。macOS 上红绿灯在左上 48 px 高的一行里，左缘 17 px。
- 中枢页面的 CSP 若写了 `connect-src`，加上 `ipc: http://ipc.localhost`，否则 IPC 退回 `postMessage`（照样能用，慢一些）。
- 快速输入页 `/app/quick` 背景透明，卡片画在 606 px 宽的窗口上部；点卡片外面时调用 `qmo_quick_hide`。失焦时壳自己隐藏窗口。
- 定义 `window.__qmoOpenSettings()`，打开页面里的设置卡片：菜单「设置… ⌘,」和托盘「设置」在主窗口显示中枢页面时由壳执行一段固定脚本调它；没有它时那段脚本回退为 `qmo_open_local_settings`（壳的设置窗）。
- 主窗口落到 `/login` 时壳拦下来重新进门，60 秒内第四次就停在离线页（`loop`）。

## 壳与运行器（本机会话）

本机会话的命令由 `src/code.rs` 转给运行器 `qmo code serve`（[`qmo-local.md`](../../../docs/dev/qmo-local.md) §4.3.2、§4.5）：

- 第一次调用时起，标准输入输出上一行一个 JSON：请求 `{id, method, params}`，应答 `{id, result}` 或 `{id, error: {code, message}}`，事件 `{method: "event", params}`。起来先发 `hello`，2 秒内答 `{version, protocol: 1, features, codeDir?}` 才算起来；`protocol` 不是 1 就结束它。
- 应答按 `id` 配给等待的调用，30 秒没答复的调用以 `qmo local E_RUNNER` 拒绝（运行器不动）。运行器的 `error` 原样变成 `qmo local <code>: <message>`（代码不是 `E_` 加大写字母时换成 `E_RUNNER`，说明压成一行、至多 500 字）。
- 事件只转给主窗口页面登记的那一条 `Channel`，按收到的顺序、原文转发；`{v: 1, type: "runner", state: "up" | "down", reason?}` 只由壳发（运行器自己不发）。
- 每条命令的参数：键、可缺省的键、交给运行器的方法与参数写在 `atlas/packages/console/test/browser/qmo-local-calls.json`，`ipc.rs` 的用例、页面的假壳与编出来的 `qmo` 的用例都核它；「字」按 UTF-16 码元计，与页面、运行器一致。
- 运行器退出：在途的调用以 `E_RUNNER` 拒绝，页面收到 `down`；1、2、5、10 秒后重起，之后每 30 秒一次（活过 60 秒的那次之后从 1 秒重来）；等待期间到的调用立即拒绝。
- 标准错误的最后 64 KiB 连同壳记的起停写进 `<codeDir>/runner.log`（0600）；运行器没报 `codeDir` 时只留在内存。
- 退出 Qmo（`RunEvent::Exit`）：不再重起，发 `shutdown` 等 3 秒，关掉它的标准输入，5 秒还在就结束进程。

## 几处取舍

- **经 `about:blank` 进中枢。** WebKit 对从另一个站点的页面出发的导航不带 `SameSite=Strict` 的 cookie，壳自己发起的也一样；骨架页在 `tauri://localhost`，直接跳过去中枢收不到会话，会一直被送去 `/login`。所以从本地页面或别的中枢去中枢时，先载入 `about:blank`、把骨架写进去，再跳。快速输入窗换中枢时直接重建，它的第一次载入本来就带得上。
- **主窗口骨架与透明窗口。** macOS 上窗口透明、背景色取页面底色（明暗随系统；页面报过颜色就用报的），页面画出来之前不会闪白。骨架页的布局与颜色由壳算成一份计划（`layout.rs`），经主窗口的初始化脚本以 JSON 交给本地页面的 `window.__QMO_BOOT__`，`skeleton.js` 在首帧前画；不拼进 HTML。
- **托盘菜单只有一处监听。** Tauri 托盘的 `on_menu_event` 也是全局的，再加应用菜单的监听，每一项会执行两次，所以只在应用上注册一次。
- **对话框插件不带页面脚本。** `tauri-plugin-dialog` 的 `init()` 会给每个页面（含中枢页面）加一段脚本，把 `window.alert`、`window.confirm` 换成它的命令；这些命令没给任何页面，`confirm` 又变成返回 Promise，同步写法 `if (!confirm(…))` 会一律当作确认（后台计费页删除上游就是这样写的）。所以注册时套一层 `code::Quiet`，只去掉这段脚本，选文件夹照用它的 Rust 接口。
- **cookie 的 `Secure`、`HttpOnly` 只在为真时写。** WKWebView 把这两个键的出现当作开启，写「否」会把 `qianmo_shell` 也变成 HttpOnly。

## 图标

应用图标和菜单栏图标都由控制台的阡陌标（`atlas/packages/console/src/view/mark.ts` 的两条路径）画成 SVG：应用图标是 824 px 圆角底板居中放标（`icons/icon.svg`），用无头 Chrome 渲染成 1024 px PNG 后交给 `cargo tauri icon` 生成各尺寸与 `.icns`、`.ico`；菜单栏图标是黑色图形、透明底的模板图（`icons/tray-template.png`，64 px，由系统着色），田埂的缝加宽，18 pt 下仍看得清。
